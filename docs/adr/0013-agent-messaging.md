# ADR-0013: Сообщения между терминалами и агентами

- Статус: Proposed
- Дата: 2026-11-09
- Дополнено [ADR-0025](0025-workspaces-and-project-catalog.md).
- Дополнено [ADR-0028](0028-agents-tab-and-threads.md): отправка от имени агента.

## Контекст

Терминалы и агенты общаются друг с другом.
Нужны действия «спросить у …» и «попросить у …».
В agterm есть почтовые ящики панелей, но они живут в памяти запуска и привязаны к панели.

## Решение

Два разных канала: ввод в терминал как явная эмуляция клавиатуры и типизированные сообщения.
Сообщение не печатается в composer агента.

Адресат это конечная точка с поколением:

- `Session { id, generation }`: любой терминал. Shell и скрипты пользуются `shellioctl msg send|read|ack`. Доставка в строку shell не выполняется.
- `Agent { id, generation }`: зарегистрированный агент, специализированный потребитель ящика своей сессии.

Адрес отправителя берётся из `SHELLIO_SESSION_ID` или явного `--as`.
Получатель задаётся явно.
Адрес не зависит от положения панели и переживает переподключение UI.

Сообщения хранятся в `state.db` и переживают перезапуск GUI.
Конверт:

```json
{
  "id": "…", "conversation": "…", "reply_to": null,
  "kind": "question|task|reply|note|cancel",
  "from": {"session": "…", "generation": 3},
  "to": {"agent": "…", "generation": 2},
  "body": "…",
  "context": [{"type": "selection|file|diff|commit|log", "ref": "…"}],
  "deadline": null
}
```

Состояния: `queued → delivered → accepted → running → replied|completed|failed|cancelled|expired`, а также `unknown`, если передача прошла, но подтверждения приёма нет.
Подтверждение транспорта не означает выполнения.

### Доставка at-least-once

Одна логическая запись на `id`, повторная транспортная доставка допустима, адаптер дедуплицирует, если умеет.
Exactly-once для действий агента не обещается.
Состояние `unknown` сверяется, автоматическая повторная отправка задачи с новым `id` запрещена.

Перезапуск агента создаёт новое поколение: старые сообщения в него автоматически не попадают, интерфейс предлагает переназначить.

Лимиты: 64 КиБ на сообщение, 256 сообщений и 1 МиБ на ящик.
Переполнение возвращает явную ошибку.

Спросить: вопрос с контекстом, ответ приходит в тред, поручения изменять проект нет.
Попросить: задача с целью, scope, worktree и критерием результата.

Сообщение агента это реплика коллеги и не даёт новых прав.
`kind: question` не лишает получателя прав на запись.
Интерфейс показывает «только чтение» лишь там, где адаптер может это обеспечить.

Для агентов, меняющих один worktree, интерфейс показывает это и предлагает отдельный git worktree.

Доставка через адаптеры: `asyncRewake`-хук у Claude Code, механизм очереди у Codex, чтение `shellioctl msg read` у остальных.
Если адаптер не поддерживает доставку или агент занят, это видно до отправки.

Агентам поставляется skill с инструкцией и CLI.

## Отвергнутые варианты

- Печать в composer: ломается при занятом вводе и обновлениях агента.
- Память без хранения: сообщения теряются при обновлении приложения.
- Адресация только агентов: требование называет и обычные терминалы.

## Последствия

Каждая новая версия агента проверяется по матрице адаптеров.
Пока приложение не запущено, поручения ждут (ADR-0004).
