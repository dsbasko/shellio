# ADR-0010: Режимы ввода и навигация в стиле nvim

- Статус: Proposed
- Дата: 2026-11-09
- Дополнено [ADR-0024](0024-main-screen-design.md): `Ctrl-\` переключает режимы в обе стороны.
- Дополнено [ADR-0025](0025-workspaces-and-project-catalog.md).
- Уточнено [ADR-0031](0031-zone-splits.md): действие `Ctrl-w v` и `Ctrl-w s`.
- Заменено [ADR-0038](0038-shipped-nvim-config.md): для управляемого nvim правило «Клавиши nvim, включая `Ctrl-o`, не перехватываются».

## Контекст

Навигация должна быть основана на движениях nvim с настраиваемыми клавишами.
При этом терминал и сам nvim владеют теми же клавишами: `Esc`, `h/j/k/l`, `Ctrl-w`, `Ctrl-o`.

## Решение

Клавиатурой управляет `KeyRouter` на уровне `NSApplication`.
Модель чистая, в `shellio-keymap`.

Порядок обработки:

1. Зарезервированные сочетания системы: источники ввода, Spotlight, Mission Control.
2. Составление текста в IME.
3. Модальный слой: палитра, диалог.
4. Контексты keymap: панель, затем режим, затем глобальные.

Режимы:

- `Navigation`: клавиши управляют приложением. Режим по умолчанию для всех панелей, кроме терминальных.
- `Input`: клавиши уходят программе или полю ввода. Режим по умолчанию для терминала, агента и редактора.

Правила:

- `Esc` в `Input` принадлежит программе.
- Выход из `Input` в `Navigation`: настраиваемое сочетание, по умолчанию `Ctrl-\`. Второе нажатие сразу после первого передаёт прежнему получателю один исходный аккорд и возвращает `Input`. `Ctrl-Space` не используется: в macOS это переключение источника ввода. Выбор проверяется на целевой системе в P0.3.
- Вход обратно: `i` или `Enter`.
- Текущий режим всегда виден в статус-баре и в рамке фокуса. Статус-бар называет получателя клавиш: «Ввод в Claude Code», «Навигация».
- При первом входе в терминальную панель рядом с поверхностью показывается подсказка про `Ctrl-\`. После первого использования она исчезает.
- В `Navigation` клавиши сопоставляются по физической клавише, поэтому команды работают при кириллической раскладке.

Клавиши `Navigation` по умолчанию:

| Клавиши | Действие |
| --- | --- |
| `j k gg G Ctrl-d Ctrl-u` | Движение внутри списков и diff |
| `h l` | Свернуть и раскрыть, назад и вглубь внутри панели |
| `Ctrl-w h/j/k/l` | Фокус между панелями и зонами |
| `Ctrl-w H/J/K/L` | Перенос панели в зону |
| `Ctrl-w v s q o = + - < >` | Сплиты и размеры |
| `Ctrl-w z` | Развернуть панель |
| `H L` | Предыдущая и следующая вкладка |
| `1`…`9` | Вкладка по номеру |
| `Space` | Лидер, подсказка which-key |
| `:` | Командная строка |
| `/` | Фильтр или поиск в панели |
| `f` | Метки для перехода к любому элементу |
| `Ctrl-o Ctrl-i` | История переходов |

Лидер-клавиши: `Space t` терминал, `Space a` новый агент (`Enter`: профиль по умолчанию), `Space q` спросить агента, `Space d` попросить агента, `Space g` git, `Space r` ревью, `Space p` пайплайны, `Space w` рабочие области, `Space Space` универсальный поиск.

`Cmd-K` открывает ту же палитру для тех, кто пользуется мышью.
Всё, что доступно мышью, доступно с клавиатуры, и наоборот.

Обычный путь работает без знания режимов:

- Клик или `Tab` в поле сразу разрешает печать. `Esc` в поле снимает фокус.
- Клик по поверхности терминала, агента или редактора включает `Input`.
- `Cmd-K` и `Cmd-,` доступны в любом режиме и из любого поля.
- `Cmd-1`…`Cmd-9` переходят в воркспейс по номеру. Это команды приложения: они работают в любом режиме и из полей, плагин не может их переопределить ([ADR-0025](0025-workspaces-and-project-catalog.md)).
- Многострочный текст: `Enter` (новая строка), `Cmd-Enter` (отправить). Однострочное поле и выбор из списка подтверждаются `Enter`.
- Закрытие наложения возвращает фокус в то же поле или панель и тот же режим.
- Фоновые события не меняют активную панель. Переход происходит только по действию пользователя и добавляет точку возврата.

Граница с nvim: поставляемый Lua-плагин вызывает `shellioctl panel focus <dir>` при достижении края окна nvim по `Ctrl-h/j/k/l`.
Клавиши nvim, включая `Ctrl-o`, не перехватываются.
Единственное исключение это выбранный аккорд выхода: `Ctrl-\` также префикс nvim, поэтому `<C-\><C-n>` набирается как `Ctrl-\ Ctrl-\ Ctrl-n`.
Удобство этого проверяется в P0.3 на `:terminal` внутри nvim.
Возврат из nvim к источнику: `Ctrl-\`, затем `Ctrl-o`, либо необязательная привязка в Lua-плагине.
Для обычного терминала `Ctrl-h/j/k/l` не перехватываются, так как `Ctrl-h` это backspace.

Keymap: `~/.config/shellio/keymap.toml` с контекстами `global`, `navigation`, `input`, `panel.<plugin>` и последовательностями вида `"<leader>gb"`.
Горячая перезагрузка.
Редактор в настройках показывает конфликты.
Некорректная привязка отключается с сообщением и не ломает остальные.

## Отвергнутые варианты

- Глобальный перехват `Esc`: ломает nvim и TUI-агентов.
- `Ctrl-Space`: занято переключением раскладки.
- Только `Cmd`-сочетания: противоречит требованию.

## Последствия

Один дополнительный аккорд на выход из терминала.
Зато программа внутри получает любые клавиши.
`Ctrl-\` в терминале означает SIGQUIT, поэтому второе нажатие передаёт его программе.

## Основания

Требования владельца, `detached/docs/KEYMAP.md`, `agterm/.claude/rules/keymap.md`, [Apple: сочетания клавиш Mac](https://support.apple.com/en-ie/102650).

## Уточнено в P0.3

Вывод [отчёта P0.3](../probes/p0.3-ghostty-surface.md) по полному автоматическому прогону 2026-11-15 на синтетических событиях.
Решение не меняется, статус остаётся `Proposed`: выбор `Ctrl-\` на целевой системе и удобство в nvim владелец не проверял, ручной проход P0.3 не проведён.

- «Сразу после»: следующее нажатие клавиши, которое не модификатор и не автоповтор первого аккорда. Миллисекундного окна нет. Удержанный `Ctrl` и нажатый между аккордами модификатор ожидание не снимают.
- Ожидание второго аккорда снимают: другая клавиша и её автоповтор, смена фокуса, щелчок и прокрутка мышью, открытие наложения, переключение приложения, закрытие получателя. Повтора после снятия нет, режим остаётся `Navigation`, щелчок по поверхности включает `Input`.
- Второй аккорд передаёт прежнему получателю сохранённое исходное событие через `ghostty_surface_key` парой нажатие и отпускание, байт вручную не пишется. Программа получает ровно `0x1c` в legacy-режиме, `CSI 92;5u` в kitty keyboard protocol с флагом 1 и пару событий нажатия и отпускания с флагами 1 и 2 (типы событий). Первый `Ctrl-\` программе не передаётся. Автоповтор первого аккорда съедается.
- При composition IME `Ctrl-\` уходит в composition, а не маршрутизатору. Открытие палитры командой при marked text снимает composition без коммита.
- В `Navigation` клавиши сопоставляются по физической клавише: `h/j/k/l` и `i` работают при кириллической раскладке.
- `Ctrl-\ Ctrl-\ Ctrl-n` в `:terminal` nvim переводит его в Normal (`mode(1)` `t` → `nt`), после первого `Ctrl-\` nvim остаётся в Terminal. `Ctrl-o` в пробе возвращает фокус на один шаг; история переходов: задача keymap, а не пробы.
- Не проверено: проходит ли `Ctrl-\` через системные сочетания и источники ввода настоящей клавиатуры (синтетические события HID и системные сочетания не проходят), удобство аккорда в nvim и в обычном терминале, `Cmd-K` клавишей при настоящем marked text.

### Что уточняет раздел «Решение»

- Объём шага подтвердил владелец. План `navigation-keymap`: чистая модель `shellio-keymap`, `keymap.toml`, `KeyRouter`, режимы, привязки названных действий P1.3-P1.5, строка статуса, история `Ctrl-o` и `Ctrl-i`, фильтр `/`. План `command-overlays`: подсказка which-key, метки `f`, командная строка `:`, палитра по `Space Space` и `Cmd-K`. Справка `?` и редактор keymap: P1.8. `:go`, провайдеры универсального поиска и `Cmd-1`…`Cmd-9`: P1.7.
- Правило «`Input`: режим по умолчанию для терминала, агента и редактора» в продукте P1.6 получателя не имеет: режим `Input` есть только у поля ввода. Заполнитель `terminal` это панель без поверхности, ввода у неё нет, она остаётся в `Navigation` до P2.2.
- Правила «Вход обратно: `i` или `Enter`» и переключение `Ctrl-\` из `Navigation` действуют только у панели с получателем ввода.
- Лидер `Space` без продолжения в плане `navigation-keymap` ждёт продолжения и ничего не показывает, подсказку which-key добавляет план `command-overlays`.
- Буква `f` остаётся в алфавите меток, метки отменяет только `Esc` (владелец). Выполняет план `command-overlays`.
- Лидер-клавиши раздела «Решение» (`Space t`, `Space a`, `Space q`, `Space d`, `Space g`, `Space r`, `Space p`, `Space w`) привязывают планы, которые строят их действия.

### Аккорд и модель

- Чистая модель: crate `shellio-keymap` (`#![forbid(unsafe_code)]`, `[lints] workspace = true`). Он зависит только от `serde`, `toml` и `serde_json`. AppKit, `shellio-core` и `shellio-plugin-api` ему не нужны: имена действий для него строки, проверку имён делает приложение по реестру. Это проверяет тест графа зависимостей.
- Аккорд хранит виртуальный код клавиши macOS и набор модификаторов `Cmd`, `Ctrl`, `Alt`, `Shift`.
- Запись в TOML и в подписях: имена прототипа. `Ctrl-w`, `Cmd-k`, `Cmd-Alt-0`, `Space`, `Enter`, `Esc`, `Tab`, буквы, `H` для `Shift-h`, знаки по раскладке US (`:`, `/`, `<`, `>`, `+`, `=`, `\`). Перевод имени в код и обратно: таблица раскладки ANSI в `shellio-keymap`.
- В `Navigation` сопоставление идёт по коду клавиши, поэтому команды работают при кириллической раскладке.
- В `Input` маршрутизатор смотрит только на контексты `global` и `input` (аккорды с `Cmd` и аккорд выхода), остальное уходит получателю.
- Последовательность не длиннее 4 аккордов. Дерево последовательностей отвечает `Exact`, `Prefix` или `None`. `Prefix`: ожидание, набранный префикс виден в строке статуса. `None`: событие идёт AppKit.

### Контексты и порядок

Порядок раздела «Решение» не меняется: модальный слой (наложения плана `command-overlays`), затем `panel.<plugin>`, затем `navigation` или `input` по режиму, затем `global`.

- Привязка панели скрывает такую же последовательность ниже.
- На один аккорд одного контекста приходится одно действие.
- Движения списка это именованные действия хоста `list.*`. Плагин, вид которого их обрабатывает, получает их привязки в своём контексте `panel.<plugin>` из общего набора хоста `LIST_KEYS` ([ADR-0008](0008-plugin-system.md)).
- Голые `h/j/k/l` в контексте `navigation` привязаны к `panel.focus.*`: это запасной переход фокуса, когда панель клавишу не обрабатывает (владелец, по прототипу). В панели со списком `j` остаётся в ней, даже когда состояние не изменилось (`j` на последней строке, `h` на свёрнутом узле), в панели без списка уходит в фокус.
- Клавиша действует на панель с фокусом видимой части открытой рабочей области. Скрытая зона, невыбранная вкладка, чужой `zoom` и заглушка ниже `min_size` клавиши не получают. Заглушка «Развернуть» с фокусом принимает `Enter` и `Ctrl-w z`.

- `Cmd-1`…`Cmd-9` остаются за P1.7 и в этом плане не привязываются.
- Деление по оси. `Ctrl-w v` привязан к оси `row`, `Ctrl-w s` к оси `stack`. Ось, не совпавшая с осью зоны ([ADR-0031](0031-zone-splits.md)), зону не делит: отказ `split_wrong_axis`, строка статуса называет действующую клавишу нужной оси из keymap («Правая зона делится одна над другой: `Ctrl-w s`»).
- Шаг размера. `layout.grow`, `layout.shrink`, `layout.wider` и `layout.narrower` меняют размер на 40 точек за нажатие, как прототип. Шаг высоты центра переводится в размер нижней зоны. При фокусе в колонке навигатора `wider` и `narrower` меняют ширину колонки, `grow` и `shrink` не действуют, строка статуса называет причину. Отказ по `min_size`: прежний отказ размера P1.4 `resize_out_of_range` ([ADR-0007](0007-control-api.md)).
- Цикл оформления `ui.appearance.cycle`: системное, светлое, тёмное.

### `keymap.toml`

```toml
leader = "Space"

[global]
"Cmd-Alt-t" = "ui.appearance.cycle"

[input]
"Ctrl-\\" = "mode.navigation"

[navigation]
"<leader>zj" = "layout.toggle.bottom"
"Ctrl-w o" = false

[panel.demo-list]
"x" = { action = "demo-list.details", args = { open = true } }
```

- Файл дополняет привязки по умолчанию. Строка с той же последовательностью и контекстом заменяет умолчание, значение `false` его снимает.
- `<leader>` раскрывается в аккорд `leader`. Последовательность это аккорды через пробел или слитно после `<leader>` (`"<leader>gb"`).
- Контексты: `global`, `navigation`, `input`, `panel.<plugin>`. Неизвестный `<plugin>`: неверная строка.
- Привязка может нести `args`, они идут тому же обработчику действия. Пример `args` из манифеста плагина никогда не подставляется ([ADR-0008](0008-plugin-system.md)).
- Неверная привязка. Каждая строка разбирается отдельно. Причины отключения: неизвестное действие, неизвестный контекст, неразборный аккорд, последовательность длиннее 4 аккордов, конфликт с другой строкой того же контекста (отключаются обе), `args`, отвергнутые проверкой действия. Отключённая строка попадает в диагностику с номером строки и причиной, остальные действуют.
- Нечитаемый TOML оставляет прежнюю таблицу и прежнюю версию, диагностика новая ([ADR-0018](0018-storage-and-config.md)).
- Сообщение в строке статуса: «keymap.toml, строка N: <причина> — привязка отключена» или «keymap.toml не прочитан: <причина> — действует прежняя таблица». Путь к файлу в сообщение не входит.

### Перехват и порядок обработки

- `KeyRouter` получает события через локальный монитор событий приложения (безопасная обёртка в `shellio-appkit`) на текущем `sharedApplication`. Подкласс `NSApplication` не нужен.
- Монитор срабатывает до `sendEvent:` и до эквивалентов меню. Вложенные циклы слежения (раскрытое `NSMenu`, перетаскивание, слежение контрола) его обходят: при раскрытом меню стрелки, `Enter` и `Esc` принадлежат штатному слежению меню.
- Обработанный `keyDown` монитор поглощает, необработанный возвращает исходным событием. Тогда стрелки списка и дерева, ввод в поле и `Esc` меню работают как в P1.3. `keyUp` и `flagsChanged` действий не исполняют: они нужны автомату аккорда выхода и пропуску автоповтора.
- Действие исполняется ровно один раз. Эквивалент пункта меню показывает действующую клавишу, но срабатывание идёт через маршрутизатор, который событие поглощает.
- Зарезервированные сочетания системы маршрутизатор не видит: их перехватывает система. При составлении текста в IME (`hasMarkedText` у первого ответчика) аккорд уходит в composition.
- Текстовое поле узнаётся по редактору поля: печатаемые клавиши без `Cmd` и `Ctrl` идут полю.
- Полоса вкладок с клавиатурным фокусом сохраняет нативные `Space` и `Enter`. Кнопка заголовка с кольцом фокуса нажимается `Space` и `Enter`, лидер при этом не срабатывает. Лидер `Space` срабатывает из тела панели.
- `app.quit` работает и без ключевого окна.

### Режим панели и получатель `Input`

- Режим хранится на панель в UI-состоянии главного потока. Обычная панель начинает в `Navigation`.
- Как только первым ответчиком фактически становится поле, панель показывает `Input`. Открытие «Демо: поле» с автоматическим фокусом в поле включает `Input` без `Tab`.
- `Esc` в поле сначала доставляет полю отмену (откат черновика без записи), затем снимает фокус с поля, если нет marked text, и панель возвращается в `Navigation`.
- Тон плитки с фокусом и линия под активной вкладкой берут режим панели: синий в `Navigation`, зелёный во `Input` ([ADR-0024](0024-main-screen-design.md)).
- Закрытие наложения (план `command-overlays`) возвращает фокус и режим.
- Действия режима: `mode.navigation`, `mode.input`, `mode.toggle`.

### Аккорд выхода

Семантика раздела «Уточнено в P0.3» переносится в продукт без изменений.

- Автомат в `shellio-keymap`: состояния `Idle` и `Armed { receiver, event }`. Окна времени нет.
- Ожидание снимают: другая клавиша и её автоповтор, смена первого ответчика или панели с фокусом, `mouseDown` и `scrollWheel`, открытие наложения, `applicationDidResignActive`, закрытие получателя. Повтора после снятия нет, режим остаётся `Navigation`.
- Повтор сохранённой пары нажатия и отпускания идёт получателю напрямую, а не через общую очередь событий.
- Аккорд настраивается: это привязка действия `mode.navigation` в контексте `input`. Автомат действует для того аккорда, который привязан.
- До P2.2 семантика проверяется на компоненте галереи «Приёмник ввода»: он вызывает настоящий маршрут и пишет журнал принятых событий. Байты PTY и kitty keyboard protocol: интеграция P2.2.
- Код пробы P0.3 в продукт не переносится ([ADR-0034](0034-probe-code.md)).

### История переходов

- История хранится отдельно от порядка фокуса раскладки: список точек на воркспейс в UI-состоянии главного потока, в базу не пишется. Точка это рабочая область, панель и режим источника.
- Каждое изменение панели с фокусом в зеркале добавляет точку, кроме перехода по самой истории и запасного фокуса после закрытия панели. Фоновые события фокус не меняют и точек не добавляют.
- `Ctrl-o` и `Ctrl-i` переходят по точкам, пропуская закрытые панели и панели вне видимых проектов.
- Переход вперёд после возврата и нового перехода отсекается: A, B, A, назад, C, вперёд пусто.
- Точка другой рабочей области того же воркспейса открывает её штатной командой `workbench.open`. Переключение воркспейса само точку не добавляет ([ADR-0025](0025-workspaces-and-project-catalog.md)).
- Глубина: 100 точек на воркспейс.

### Строка статуса

- Слева плашка режима «НАВИГАЦИЯ» или «ВВОД». Это кнопка, нажатие вызывает `mode.toggle`.
- Затем либо сообщение, либо набранный префикс, либо подсказки из действующего keymap, не больше трёх ([ADR-0023](0023-opaque-window-and-shell.md)).
- Порядок подсказок в `Navigation`: свои подсказки панели (до трёх); иначе «панели» (действующие клавиши `panel.focus.*`), «вкладки» (`1 2 3`), «поиск» (клавиша `palette.open`, если действие зарегистрировано). У панели с вводом «вкладки» заменяет «ввод» (клавиша `mode.input`).
- Во `Input` поля: «Esc навигация».
- Сообщение отказа или ошибки keymap замещает подсказки до следующего действия пользователя, плашка остаётся.
- Правило раздела «Решение» «Статус-бар называет получателя клавиш» для терминала и агента выполняют P2.2 и P2.5.

### Фильтр `/`

`/` привязан к действию `panel.filter` (владелец).
Плагин объявляет поддержку в манифесте, строку фильтра рисует хост, сужение строк делает плагин ([ADR-0008](0008-plugin-system.md)).
В P1.6 фильтр реализует «Демо: список».

### Прототип приводится к ADR

Правки прототипа подтвердил владелец при планировании, порядок по задачам записан в [ADR-0037](0037-prototype-conformance.md).
К этому ADR относятся три: второй `Ctrl-\` без окна 450 мс, не больше трёх подсказок в строке статуса, фокус в поле переводит панель во «ВВОД».

Передачи:

- плану `command-overlays`: палитра, which-key, метки `f`, `:`, вход `Space Space` и `Cmd-K`, подсказка «поиск» строки статуса;
- P1.7: `Cmd-1`…`Cmd-9`, имена keymap действий над воркспейсами, проектами и рабочими областями, `:go`;
- P1.8: редактор keymap с записью сочетания и конфликтами, справка `?` из той же таблицы;
- P2.2: терминал как получатель `Input` по умолчанию, байты PTY и kitty keyboard protocol для повтора исходной пары, подсказка про `Ctrl-\` при первом входе, аккорд под нелатинскими раскладками в терминале;
- P3.6 и P3.7: граница с nvim по действующей таблице keymap ([ADR-0007](0007-control-api.md));
- первому плану, которому они понадобятся (P3.2 или P3.6): позиции внутри панели в истории переходов. Точка P1.6 позицию внутри панели не хранит;
- владельцу: `Ctrl-\` на настоящей клавиатуре через системные сочетания и источники ввода.
