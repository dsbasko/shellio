# ADR-0017: Редактор как nvim в терминальной панели

- Статус: Proposed
- Дата: 2026-11-09

## Контекст

Редактор кода под капотом — это nvim.

## Решение

Плагин `editor` запускает `nvim --listen <socket>` в терминальной панели libghostty через ту же сессию, что и у терминала. Конфигурация пользователя сохраняется.

Интеграция идёт через RPC-сокет:

- Открыть файл на строке из diff, blame, ревью и пайплайнов. Панель выбирается по политике: существующий редактор рабочей области или новый.
- «Назад к источнику» возвращает фокус и прокрутку в исходную панель.
- Поставляемый Lua-плагин вызывает `shellioctl` для перехода между панелями и отчитывается о текущем файле.

Историческая ревизия открывается как буфер только для чтения. Worktree рабочей области определяет каталог запуска. Клавиши внутри редактора принадлежат nvim.

Плагин `editor` требует установленного `nvim`, при отсутствии показывает ошибку с действием.

## Отвергнутые варианты

- `nvim --embed` со своей отрисовкой сетки: новый рендер без выгоды, поскольку терминал уже есть.
- Собственный редактор: вне требований.

## Последствия

Редактор наследует всё поведение терминала. Интеграция ограничена тем, что доступно по RPC.

## Основания

[Neovim: remote и embed](https://neovim.io/doc/user/starting/).

## Условие пересмотра

Появление требований, которые нельзя выполнить в терминальном nvim.
