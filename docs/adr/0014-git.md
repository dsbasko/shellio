# ADR-0014: Работа с git и commit message

- Статус: Proposed
- Дата: 2026-11-09

## Контекст

Нужны незакоммиченные изменения, diff, выбор файлов и строк, commit с AI-сообщением, blame и просмотр коммитов.

## Решение

Git вызывается как внешняя команда `git` через runner с таймаутами, отменой и лимитом вывода. Форматы машинные: `status --porcelain=v2`, `blame --porcelain`, `log` со своим форматом. Так работают хуки, credential helpers, конфигурация пользователя и нестандартные пути.

`RepositoryService` общий, но статус, diff, кэш index и очередь его изменений имеют ключ `WorktreeId`. Подписки адресуют конкретный worktree. На уровне репозитория кэшируются только общие объекты и refs.

**Выбор — это настоящий index.** Галочка на файле, ханке или строке меняет index немедленно. Частичная подготовка строит патч и применяет его через `git apply --cached`. Панель показывает весь index, включая то, что туда добавил агент или терминал. Галочка не обещает, что в commit попадёт только выбор этой панели.

Commit:

- Отдельные действия: выбрать → проверить итоговый diff → commit. Генерация текста сама ничего не индексирует и не коммитит.
- Изменения index из приложения выполняются последовательно, короткими операциями. `index.lock` не удерживается во время генерации.
- Сбой хука оставляет текст сообщения и выбор, вывод хука доступен.
- Состояния «нет изменений», rename, binary, конфликт и detached HEAD показаны явно.

**Граница гарантий.** Index общий с агентами и терминалом, поэтому между проверкой и `git commit` кто-то может выполнить `git add`, и commit заберёт и это. Приложение снижает риск проверкой перед commit и сообщает о расхождении после него, но строгой гарантии не даёт и созданный commit не переписывает. Запрещены `git commit -- <path>` (ломает частичную индексацию) и ручное удержание `index.lock`.

AI-сообщение — отдельная одноразовая отменяемая задача, не касающаяся идущих диалогов: профиль с `claude -p`, `codex exec` или своей командой, шаблон `~/.config/shellio/prompts/commit.md`, вход — diff index. Свежесть определяется по репозитории и worktree, `HEAD` и OID дерева index. Вывод потоком идёт в поле ввода. Ручной текст не перезаписывается, при изменении дерева результат помечается устаревшим и предлагается повторить.

Blame: `PerWorkbench`. Строка → коммит → файлы коммита → diff файла. «Назад» возвращает к прежней строке и прокрутке. Загрузка инкрементальная и отменяемая.

Историческая ревизия в редакторе открывается только для чтения.

## Отвергнутые варианты

- Теневой index, как changelists в JetBrains: агенты в том же worktree не увидят выбор, и получатся два источника правды.
- libgit2 и gitoxide как основа: расхождения с хуками и конфигурацией. Gitoxide можно применить точечно для тяжёлого чтения по замерам.

## Последствия

Зависимость от установленного `git`. Для массовых операций нужна осторожность с количеством процессов.

## Основания

`detached/crates/core/src/git` (runner, отмена, лимиты), `agterm/ARCHITECTURE.md` (Git status: таймауты и стоки вывода).

## Условие пересмотра

Замеры покажут, что запуск процессов — узкое место.
