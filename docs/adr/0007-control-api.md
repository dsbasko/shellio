# ADR-0007: Управляющий API и CLI

- Статус: Proposed
- Дата: 2026-11-09

## Контекст

Терминал и всё приложение должны полностью управляться внешними вызовами, чтобы фоновые задачи и агенты могли работать с ними.

## Решение

Единый слой команд: действие из меню, по клавише, из палитры и из CLI вызывает один и тот же типизированный `Command` с одним обработчиком. Новое действие считается законченным, когда у него есть команда, CLI, чтение результата и тесты.

Транспорт: Unix-сокет с правами `0600` и проверкой UID собеседника, JSON построчно, лимит 1 МиБ на запрос. Первая команда клиента — `hello` с версией протокола. Ошибки структурированы и имеют стабильные коды. Путь сокета короче 104 байт.

CLI `shellioctl` (названия уточняются в P1.2):

- `tree`, `status`, `version`
- `workspace|project|workbench list|new|open|focus|rename|close`
- `panel list|open|focus|move|hide|close-view|remove`
- `pane text|type|paste|run|search|resize|copy`
- `session list|start|stop|attach`
- `agent list|start|status|ask|task|cancel`
- `msg send|read|ack`
- `events --since <cursor>`, `metrics`, `keymap reload`, `config reload`

Цель всегда задаётся явно (`--target`) либо берётся из окружения `SHELLIO_SESSION_ID`, `SHELLIO_PANEL_ID`, `SHELLIO_SOCKET`. Команда с явной целью не зависит от текущего фокуса.

Вывод — JSON с `--json`, иначе человекочитаемый. Каждая команда, меняющая состояние, видна в `tree` или в собственном чтении.

События: журнал с монотонным курсором. Клиент, потерявший поток, получает снимок и ревизию. Команды, которым нужен UI при закрытом окне, возвращают явный результат `no-ui`.

Сокет защищает от других пользователей, но не изолирует процессы одного пользователя.

Потоковая трансляция вывода терминала в протокол не входит. Чтение экрана — разовая команда.

## Отвергнутые варианты

- Отдельный API для CLI: логика разойдётся с интерфейсом.
- gRPC и HTTP: лишний вес для локального канала.

## Последствия

Плагин, добавляющий действие, обязан объявить его как команду. Ручное действие без команды — дефект.

## Уточнено в P1.1

Решение плана P1.1 `core-domain`, принятое при планировании 2026-11-21. Слой команд и транспорт не меняются.

- **Команды P1.1:** `workspace.create`, `workspace.rename`, `project.add`, `workbench.create`, `workbench.rename`, `workbench.open`, `window.focus_workspace`. **Чтения:** `query.tree` с явной областью `Workspace(id)` или `All` ([ADR-0025](0025-workspaces-and-project-catalog.md): внешний CLI без контекста сессии задаёт область сам) и `query.status`.
- **Формат JSON.**
  - `Command` — внутренний тег `cmd` с именем команды, поля в `snake_case`: `{"cmd":"workspace.create","title":"Работа"}`. Имена в команде — строки как есть: пустое или неверное имя отвергает обработчик кодом `invalid_argument`, а не разбор.
  - `Query` — `{"query":"tree","scope":{"workspace":"…"}}`, `{"query":"tree","scope":"all"}` или `{"query":"status"}`.
  - `Reply` — `{"revision":12,"value":{…}}`. Значение без тега: дерево, состояние хранилища или значение команды — `{"workspace":…}`, `{"project":…,"root":…}`, `{"workbench":…}` или `null`. Варианты различаются набором полей, поэтому разбор однозначен.
  - `Event` — `{"revision":12,"changes":[{"change":"workspace_renamed",…}]}`.
  - `Snapshot` — `{"revision":12,"state":{…}}`, `EventsSince` — `{"events":[…]}` или `{"reset":снимок}`.
  - `CoreError` — `{"code":"root_taken","message":"…","retryable":false,"details":{…}}`. `retryable` следует из кода: повтор только у `storage_unavailable` и `busy`. Разбор `CoreError` с `retryable`, не совпадающим с кодом, отказывает.
  - Лишнее поле и неизвестный вариант отвергаются у всех типов границы, входящих и исходящих, включая записи модели в снимке. Порядок ключей объекта в контракт не входит: эталоны сравниваются как значения JSON.
- **Стабильные коды ошибок:** `invalid_argument`, `not_found`, `name_taken`, `root_taken`, `storage_unavailable`, `storage_conflict`, `busy`, `shutting_down`. Имена команд, чтений, изменений и коды закреплены эталонными JSON в `crates/shellio-core/tests/wire/`. После P1.1 они не переименовываются: новый смысл получает новый вариант.
- **Детали отказа:**
  - `invalid_argument` — `field` и `reason`, у пути ещё `path`;
  - `not_found` — `entity` и `id`;
  - `name_taken` — `entity`, `name` и `existing`;
  - `root_taken` — `project` и `workspace` владельца корня.
- **Стабильные причины `invalid_argument`:**
  - имя: `title_empty`, `title_too_long`, `title_control_char`, `title_required` (у канонического пути корня нет последнего компонента в UTF-8, имя по умолчанию не вычисляется);
  - путь корня: `path_not_absolute`, `path_not_found`, `not_a_directory`, `path_unreadable`, `path_not_utf8`, `git_link_invalid` ([ADR-0025](0025-workspaces-and-project-catalog.md), «Уточнено в P1.1»);
  - позиция: `position_exhausted` с деталью `scope` (`workspaces`, `project_list`, `workbenches`) — после наибольшей позиции родителя места нет;
  - курсор: `cursor_ahead` — курсор событий больше текущей ревизии.
- **Скрытые записи.** Удалённый воркспейс, убранный проект, проект удалённого воркспейса и рабочие области таких проектов для команд — `not_found`, удалённый или несуществующий воркспейс в области `query.tree` — тоже: дерево их не показывает.
- **`query.status`** сообщает ревизию, версию схемы, путь `state.db` и диагностику загрузки `{table, rowid, reason}` со стабильными причинами ([ADR-0018](0018-storage-and-config.md), «Уточнено в P1.1»).
- **Ревизия.** Ревизия хранится в `state.db` и растёт в той же транзакции, что и изменение, поэтому монотонна через перезапуски. Курсор событий — ревизия. Журнал событий живёт в памяти: курсор старше буфера или из прошлого запуска получает снимок и ревизию. Загрузка с находками значит, что базу правили в обход ядра: запуск тогда пишет одну запись, пусть и без дельт, и не кладёт её в журнал, поэтому снимок получает и курсор, равный ревизии загрузки, а курсор этого запуска — пустой список. Команда, не меняющая состояние, отвечает без новой ревизии и без события: переименование в то же имя, фокус активного воркспейса, открытие уже открытой рабочей области. Переименование, меняющее только регистр, — изменение.
- Внутренние команды запуска ядра (первый воркспейс, когда нет ни одного неудалённого, фокус, когда активный воркспейс пуст или удалён, и маршрут активного воркспейса, когда окно ведёт в скрытую рабочую область) в `Command` не входят и в JSON не сериализуются. Их изменения идут обычными событиями.
- **Законченное действие в P1.1 — частично:** команда, обработчик, чтение результата и тесты.
  - CLI каждой команды и чтения P1.1 — обязательная часть P1.2: `workspace new|rename|focus`, `project add`, `workbench new|rename|open`, `tree`, `status`. Вместе с ними P1.2 вводит конверт запроса с номером, `hello` с версией протокола, `events --since` и проверку области по ADR-0025.
  - Имя в keymap и UI этих действий — P1.7.

## Условие пересмотра

Потребность в управлении с другой машины.
