# ADR-0004: Модель процессов и время жизни сессий

- Статус: Proposed
- Дата: 2026-11-09

## Контекст

Главная ценность приложения — долгие терминальные и агентские сессии. Автообновление и падение интерфейса не должны их убивать. При этом полный libghostty сам запускает команду поверхности и не принимает внешний PTY.

## Решение

Процессы:

| Процесс | Владеет | Живёт |
| --- | --- | --- |
| `shellio` (GUI) | `NSWindow`, поверхности libghostty, ядро команд, плагины, управляющий сокет, сообщения, сэмплер | Пока приложение запущено |
| `shellio-host`, по одному на сессию | PTY master, дочерний процесс, состояние экрана, snapshot | Независимо от GUI, пока жива сессия |
| Attach-клиент | Мост между поверхностью libghostty и хостом | Расходуемый, живёт вместе с поверхностью |
| Процессы пользователя | shell, агенты, nvim, git | Внутри сессии |

Схема с двумя PTY. Поверхность libghostty запускает attach-клиент в своём PTY. Настоящие shell и агент работают во втором PTY, которым владеет хост, запущенный в отдельной сессии (`setsid`). Перезапуск GUI уничтожает только клиента. Повторное подключение никогда не запускает нагрузку заново.

Создание сессии идёт отдельно от поверхности, через атомарное `create-or-attach` по стабильному `SessionId`. Запуск нагрузки не ждёт создания поверхности, что также закрывает случай спящего дисплея.

Ядро команд — UI-free crate, работающий внутри процесса GUI на своём потоке, за транспортной границей. Отдельный брокер в первой версии не вводится.

Контракт доступности первой версии:

- Управляющий API и доставка сообщений работают, пока запущено приложение.
- При недоступном приложении CLI возвращает явную ошибку с признаком повторной попытки. Очередь не теряется, доставка возобновляется при следующем запуске.
- Закрытие окна приложение не завершает, поэтому обычный уход от компьютера контракт не нарушает.
- `shellioctl` и адаптеры не пишут в `state.db` напрямую. Единственный писатель — ядро.

Триггер выделения брокера: появление обязательных операций CLI или сообщений при отсутствующем GUI. Тогда ядро переносится в свой процесс как единственный писатель, а GUI становится проекцией его состояния.

Контракт времени жизни:

| Событие | Панель | Процессы сессии |
| --- | --- | --- |
| Скрыть или перенести панель | Состояние сохраняется | Живут |
| Закрыть панель с простаивающим shell | Закрывается | Завершаются |
| Закрыть панель с работающей программой или агентом | Выбор в одну клавишу: закрыть вид или остановить | При закрытии вида живут и доступны в навигаторе, при остановке завершаются |
| Закрыть окно macOS | Приложение остаётся в Dock | Живут |
| `Cmd-Q` | Подтверждение, только если работают агенты | Живут по умолчанию, вариант «Завершить всё» |
| Падение GUI | Восстановление при следующем запуске | Живут |
| Обновление | Перезапуск GUI, те же сессии | Живут на старом runtime |
| Потеря хоста | Состояние «хост потерян», контекст сохранён, проверка процессов по PID и времени старта | Могут продолжать работать. Показываются найденные процессы и действия «Остановить оставшиеся» и «Запустить новую» |
| Выход из системы, перезагрузка | Раскладка восстанавливается | Завершены, новая сессия запускается по запросу |

Команды разделены: `panel.hide` скрывает, `panel.close_view` закрывает вид и оставляет сессию, `session.stop` останавливает процессы, `panel.remove` убирает панель из раскладки. `×` и `Ctrl-w q` выполняют закрытие по таблице выше. Успех `session.stop` проверяется по процессам, а не по исчезновению сокета.

Транскрипт никогда не показывается как живой терминал. Второй экземпляр агента автоматически не запускается. Гарантии не распространяются на программы, которые сами стали демонами и покинули дерево сессии.

Живая сессия — это три свойства: процесс жив, вывод читается, состояние корректно показывается при повторном подключении. Проба P0.4 проверяет все три.

## Отвергнутые варианты

- PTY внутри GUI: простое решение, но каждое обновление завершает всех агентов.
- Демон-брокер `shelliod` сразу: добавляет IPC проекций, регистрацию службы и согласование версий. Его цена оправдана, только если работа агентов должна продолжаться без GUI.
- Один общий демон на все PTY: его падение убивает все сессии.

## Последствия

- Если GUI упал и не запущен снова, живые агенты продолжают работать, но поручения между ними стоят до следующего запуска приложения.
- Хосты могут остаться незаметно работающими после выхода. Вариант «Завершить всё» и панель Resources делают их видимыми.
- Атрибуция TCC для хостов, переживших обновление, проверяется в P0.5. В agterm для этого используется приватный `responsibility_spawnattrs_setdisclaim`. Его применение решается по результатам пробы и не считается бесплатной предпосылкой.
