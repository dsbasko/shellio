# ADR-0025: Воркспейсы как глобальное разделение и каталог проектов

- Статус: Accepted (решение владельца)
- Дата: 2026-11-10
- Дополняет [ADR-0001](0001-vocabulary.md), [ADR-0007](0007-control-api.md), [ADR-0008](0008-plugin-system.md), [ADR-0010](0010-input-and-navigation.md), [ADR-0013](0013-agent-messaging.md) и [ADR-0015](0015-forge-review.md). Заменяет раздел «Навигатор» в [ADR-0024](0024-main-screen-design.md) и правило «один фиксированный состав» в [ADR-0023](0023-opaque-window-and-shell.md).

## Контекст

Сейчас воркспейсы показаны разделами дерева в навигаторе, рядом с проектами. Владелец требует другого: воркспейс глобально делит рабочее пространство, например на «Личное» и «Работа», и воркспейсы не пересекаются. Внутри одного воркспейса могут быть сотни проектов. Их нужно добавлять, удалять, скрывать и переименовывать. Постоянно на виду остаются только проекты, которые выбрал пользователь.

Дерево с шевронами на таком объёме не работает, а фоновая работа по каждому проекту стоила бы CPU, памяти и запросов к GitHub и GitLab.

## Решение

### Граница

- В окне активен один воркспейс, и он определяет всё, что видно в окне. По умолчанию окно одно.
- Проект принадлежит ровно одному воркспейсу, корень проекта ровно одному проекту. Ключ корня: общий git-каталог у репозитория, канонический путь у обычной папки.
- Попытка добавить занятый корень предлагает открыть его там, где он уже есть, или перенести сюда.
- Два отдельных клона одного remote разрешены. Локальные черновики ревью принадлежат проекту, поэтому не видны из другого воркспейса. Сам MR на сервере общий по природе сервиса.
- Это граница от ошибок и шума, а не песочница: процессы одного пользователя видят одну файловую систему.

| Поверхность | Область |
| --- | --- |
| Навигатор | Активный воркспейс |
| Поиск | Активный воркспейс. Все его проекты, включая проекты вне списка, и сессии с подписью «проект / область». Из других воркспейсов доступны только их названия для перехода |
| Статус-бар: ветка, CI, агенты, ревью | Активный воркспейс |
| Центр агентов, очереди, треды | Активный воркспейс |
| «Спросить», «попросить», сообщения между сессиями | Только внутри воркспейса |
| Уведомления и их действия | Свой поток у воркспейса. Действие не истекает, пока пользователь находится в другом воркспейсе |
| История `Ctrl-o` | Своя у воркспейса. Само переключение в неё не записывается |
| Аккаунты GitHub и GitLab, переопределения проектов, история терминалов, восстановление сессий | Данные и списки ограничены воркспейсом. Секреты физически лежат в одном Keychain |
| Тема, keymap, обновление, настройки приложения | Глобально |
| Ресурсы | Измеренные процессы активного воркспейса, остальные воркспейсы одной суммой, отдельно GUI и общие службы, оценки с `≈`. Память других воркспейсов не вычисляется вычитанием |

Область фиксируется в момент вызова команды. Асинхронная операция завершается в своём воркспейсе, даже если окно уже переключили. Единственное исключение описано в правилах переноса.

### Сигналы между воркспейсами

По умолчанию сигналов нет. Настройка «Показывать внимание других воркспейсов» добавляет у переключателя число без имён, а его поповер разбирает это число по воркспейсам. Считаются только актуальные причины: агент ждёт ответа, последний запуск текущей ревизии упал у тёплого проекта. Ради метки холодные проекты не прогреваются.

### CLI и сообщения

- Область проверяется на сервере команд: для чтения, адресных команд, подписок и доставки очереди.
- Команда из сессии получает область через `SessionId`, а не из запечённого окружения. `--target` и `--as` её не расширяют.
- Внешний `shellioctl` без контекста сессии использует явные `--workspace` или `--all`. Управление другим воркспейсом не переключает окно без явной команды.
- Сообщения между сессиями разных воркспейсов запрещены в любом случае.

### Переключение

- Первая крошка заголовка становится заметной кнопкой с шевроном и именем «Воркспейс: Работа». Она открывает поповер: воркспейсы с галочкой у активного, постоянные номера, «Новый воркспейс», «Управление проектами…».
- `Cmd-1`…`Cmd-9` переходят в воркспейс по номеру. Это команды приложения, как `Cmd-K`: работают в Вводе и из полей, плагин не может их переопределить. `Space ⇧W` открывает поповер.
- Открытый sheet блокирует переключение. Немодальные поповеры закрываются, начатая последовательность клавиш сбрасывается, черновики остаются у источника.
- Переключение ничего не останавливает ([ADR-0004](0004-process-model.md)). Возврат восстанавливает последнюю рабочую область, панель, режим и положение списков, но не старое подтверждение.
- Окно хранит активный `WorkspaceId`. Маршрут принимает значения `WorkspaceHome` или `Workbench`. Воркспейс рабочей области выводится через её проект.
- `WorkspaceHome` показан, когда открывать нечего, например в пустом воркспейсе. На нём приглашение добавить проект и та же модель каталога. Фиктивные проекты и области не создаются.

### Навигатор

Навигатор показывает короткий список проектов, выбранных вручную. Остальные проекты воркспейса в нём не появляются и доступны через выбор, поиск и каталог. У проекта два состояния видимости: в списке с ручной позицией и вне списка. Вне списка является обычным состоянием, а не ограничением: работа, поиск и переход не меняются.

- Один раздел «Проекты». В заголовке счётчик «4 из 345» и постоянная кнопка `+`. Счётчик считает участников списка и зарегистрированные проекты, без убранных и без временной строки.
- Список меняется только действием пользователя. Открытие проекта и работа в нём его не добавляют. Добавление не открывает проект и не запускает его области.
- Текущий проект вне списка показан последней строкой с пометкой «Вне списка» и обычным контрастом. Строка исчезает при уходе. Скрытие текущего проекта переводит его в эту строку, рабочая область, панели и фокус не меняются, курсор остаётся на проекте.
- Текущий проект раскрыт автоматически. Другие можно раскрывать одновременно с ним, это запоминается.
- `Enter` и щелчок открывают последнюю рабочую область. `l` и шеврон раскрывают, `h` сворачивает.
- `/` фильтрует список, ниже идёт раздел «Не в списке» с совпадениями среди остальных проектов. `Enter` открывает проект, `x` показывает его в списке, запрос и курсор сохраняются.
- Курсор и положение прокрутки привязаны к `ProjectId`.
- Список проектов прокручивается сам. «Сессии» и «В фоне» текущей области остаются внизу и занимают не больше 40 % высоты.
- Проектов нет: приглашение добавить папку. Проекты есть, список пуст: кнопка «Выбрать проекты». Проект вне списка открыт: временная строка, переход на `WorkspaceHome` не выполняется.

### Выбор проектов

`+`, `a` и команда палитры открывают поповер «Проекты в списке»: поиск и все проекты воркспейса с галочками. Сначала участники списка в его порядке, затем недавно открытые, затем остальные по имени.

- Порядок строк фиксируется на время открытия, галочки и курсор привязаны к `ProjectId`.
- `Enter` и щелчок переключают галочку и применяются сразу, поповер остаётся открытым. Текст запроса выделяется, следующий ввод его заменяет. `Esc` закрывает, применённое остаётся.
- Искать можно по имени и корню. Выдача ограничена 100 строками с подписью «Показано 100 из 183» и переходом в каталог с переносом запроса.
- Внизу постоянные действия «Добавить папку…», «Клонировать…», «Найти в папке…». В воркспейсе без проектов открывается сразу добавление.

### Операции

Клавиши действуют в Навигации на выбранной строке проекта. `a` работает и в пустом списке.

| Действие | Смысл | Правила | Клавиша | CLI |
| --- | --- | --- | --- | --- |
| Добавить | Папка, несколько папок, клонирование по URL, поиск репозиториев в папке | Указанная папка и клон попадают в список. Поиск в папке заносит в каталог вне списка независимо от числа находок, сам ничего не открывает и даёт для каждого нового репозитория галочку «Показать слева». Первая рабочая область создаётся при первом открытии. Путь убранного проекта возвращает тот же проект с его прежней видимостью | `a` в выборе | `project add`, `project scan` |
| Переименовать | Меняет только показанное имя | Папка и идентификатор не меняются. Имя уникально внутри воркспейса. Правка в строке | `r` | `project rename` |
| Показать в списке, скрыть из списка | Меняет только видимость в навигаторе | Показанный попадает в конец. `J` и `K` меняют порядок участников списка без фильтра. Сессии работают, остаются в статус-баре и поиске сессий | `x` | `project show`, `hide` |
| Перенести | В другой воркспейс | См. ниже | `m` | `project move` |
| Убрать из каталога | Исключает проект из каталога и выбора | Папки и worktree на диске не затрагиваются никогда, процессы не останавливаются. См. ниже | `D` | `project remove`, `restore`, `forget` |

Воркспейс создаётся, переименовывается и упорядочивается теми же средствами.

**Видимость.** Показ и скрытие применяются сразу, в том числе массовые: они идемпотентны над набором и дают одну отмену для фактически изменённых записей. Отмена является явным показом, а не переключением. Она адресует `ProjectId`, не открывает проект и не меняет воркспейс, повторно проверяет запись. Прежняя позиция восстанавливается, если свободна, иначе проект идёт в конец. Убранный или забытый проект отмена не возвращает. После переноса показ относится к новому воркспейсу и ставит проект в конец. Уведомление о массовом действии следует за своим набором. Если набор разошёлся по воркспейсам, отмена делится и действует только на проекты своего воркспейса.

**Перенос.** Живые процессы разрешены и не перезапускаются, поколение не меняется. Уже запущенные процессы сохраняют своё окружение. В целевом воркспейсе выбирается допустимый аккаунт, иначе операции с GitHub и GitLab приостанавливаются: кнопки внешних записей приглушены, рядом указана причина.

Перенос блокируют поручения и очереди, связывающие переносимый набор с проектами вне него, и идущие внешние записи или асинхронные операции самого набора. Показывается их список, пользователь дожидается завершения, отменяет их или переносит связанные проекты вместе.

Внутренние треды, очереди и уведомления набора меняют воркспейс в одной транзакции с проектом. Это единственное исключение из фиксации области в момент вызова. Межпроектная история остаётся в исходном воркспейсе.

Проекты набора, бывшие в списке, встают в конец списка цели одним блоком с сохранением взаимного порядка. Проекты вне списка остаются вне списка.

Перенос текущего проекта из интерфейса уводит окно за ним. Перенос из CLI не переключает воркспейс: окно уходит на последнее допустимое место в своём воркспейсе или на `WorkspaceHome`, а уведомление предлагает перейти к перенесённому проекту. Пока открыт sheet этого проекта, CLI получает отказ с причиной.

**Убрать из каталога.** Выполняется сразу и ничего не останавливает. Проект исключается из каталога и выбора, но сохраняет `ProjectId`, воркспейс, корни, позицию в списке, сессии, черновики, очереди и журнал внешних операций. Уведомление «Проект убран из каталога. 2 сессии продолжают работу» несёт действие «Вернуть проект». Остановка сессий остаётся отдельным действием. Текущий вид сохраняется до ухода из него, чтобы не оборвать ввод.

Живые сессии убранного проекта видны в поиске и ресурсах своего воркспейса с именем проекта и пометкой «Убран из каталога».

Проект вне списка остаётся обычным зарегистрированным. Убранный виден только среди убранных в каталоге, его сохранённые раскладки не запускают работу, а новое открытие начинается с возврата проекта.

Автоматического срока хранения нет, чистятся только восстановимые кэши. Запись стирается лишь явной командой «Забыть проект» в каталоге и только когда за ней нет незавершённой работы: живых сессий, черновиков, незавершённых сообщений и поручений, выполняющихся запросов и внешних операций с неизвестным результатом до их сверки.

Корень остаётся за проектом, пока запись не забыта. Повторное добавление пути возвращает тот же проект. Если он убран в другом воркспейсе, пользователь выбирает вернуть его там или перенести сюда по правилам переноса.

Воркспейс можно удалить, только если в нём нет зарегистрированных проектов и незавершённой работы у убранных. Проверка та же, что у «Забыть проект», черновики её блокируют. Убранные проекты без незавершённой работы уходят вместе с ним и возвращаются только вместе с ним. Удаление воркспейса обратимо. Последний воркспейс удалить нельзя.

### Каталог

Плагин `projects` («Все проекты») открывается командой «Управление проектами…». Таблица в центре, список и детали в боковой зоне, одна модель и одна выборка `ProjectId`. Разделы «Все», «В списке» с сортировкой как в навигаторе и «Убранные», строки вне списка не приглушаются. Сортировка, множественный выбор, поиск репозиториев в папке. Массовая команда сначала показывает состав и препятствия, кроме показа и скрытия. Кардинальность новая: `PerWorkspace`, у каждого воркспейса одна панель со своими фильтрами.

### Масштаб

- Проект тёплый, пока есть видимый потребитель, живая сессия, идущая операция или явно включённое наблюдение. После освобождения и короткого простоя наблюдатели и опрос останавливаются.
- Сохранённая раскладка не делает проект тёплым. Она хранится без запуска плагинов и сети.
- Опрос GitHub и GitLab имеет общий лимит параллельности и частоты.
- Запуск не делает обхода файлов, сетевых запросов и восстановления панелей по всем проектам. Отсутствие папки выясняется при открытии.
- Выдача навигатора, выбора и каталога виртуализирована или постраничная.

### Хранение

`workspaces(id, title, position, deleted_at)`, `projects(id, workspace_id, title, list_position, removed_at, last_opened_at)`, `project_roots(id, project_id, key UNIQUE)`. Убранный проект сохраняет свои корни, поэтому отдельный признак активности не нужен. Всё адресуется идентификаторами, а не именами.

## Отвергнутые варианты

- Разделы воркспейсов в навигаторе. Не разделяют пространство глобально.
- Отдельный экземпляр приложения на воркспейс. Противоречит [ADR-0006](0006-single-instance.md).
- Вертикальный ряд значков воркспейсов. Отнимает ширину ради нескольких воркспейсов.
- Один корень в нескольких воркспейсах. Нарушает требование непересечения.
- Метка внимания других воркспейсов включённой по умолчанию. Требование владельца запрещает пересечение, пусть и только по вниманию.
- Все проекты воркспейса в навигаторе, хотя бы отдельным разделом или свёрнутой строкой. Сотни строк засоряют рабочую область, требование владельца это запрещает.
- Навигатор с автоматическим набором недавних. Открытие проекта меняло бы список без действия пользователя.
- Закрепление отдельно от скрытия. Три состояния там, где владельцу нужны два.
- Удаление как «Удалить из воркспейса». Проект сохраняет принадлежность, корни и работу.
- Разделы «Недавние» и «Все» с переносом строки между ними. Открытие проекта меняло бы его место, а «Все» не содержали бы всех.
- Физическое удаление папки из приложения. Владелец определил удаление как исключение из списка.
- Обязательная остановка сессий при удалении. Убрать из списка и остановить процесс — разные действия.
- Автоматическое стирание убранных проектов через срок. Терялись бы неотправленные черновики и владелец ещё живых процессов.

## Последствия

- Левая колонка главного экрана перестаёт совпадать с `Main.dc.html`: строки воркспейсов уходят, появляется один ручной список проектов. В первой крошке заголовка появляется шеврон. Центр, правая и нижняя зоны и статус-бар не меняются.
- Каждое действие из таблицы оформляется по правилу `AGENTS.md`: команда, обработчик, CLI, чтение результата, тесты и имя в keymap.
- `Cmd-1`…`Cmd-9` в странице прототипа могут конфликтовать с браузером. Там работают крошка, `Space ⇧W` и поиск.
- [ADR-0008](0008-plugin-system.md) получает кардинальность `PerWorkspace`. [ADR-0010](0010-input-and-navigation.md) получает исключение для `Cmd-1`…`Cmd-9`. [ADR-0015](0015-forge-review.md) получает принадлежность черновиков проекту.
- Изменения затрагивают планы P1.1, P1.2, P1.4–P1.7.

## Основания

Требование владельца от 2026-11-10: воркспейс делит рабочее пространство глобально, воркспейсы не пересекаются, проектов могут быть сотни, их можно добавлять, удалять, скрывать и переименовывать. Удалить означает убрать проект из каталога, файлы на диске не затрагиваются.

Уточнение владельца от того же дня: проекты, кроме выбранных, не отображаются в списке слева, чтобы не засорять рабочую область, а добавлять проекты в зону видимости и прятать их оттуда должно быть легко.

## Условие пересмотра

Требование показывать несколько воркспейсов одновременно или синхронизация между машинами.
