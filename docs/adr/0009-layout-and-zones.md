# ADR-0009: Раскладка, четыре зоны и адаптация панелей

- Статус: Accepted (вывод P1.4 по правилу плана, [ADR-0036](0036-autonomous-execution.md)): отрицательных выводов по модели нет. Деревья сплитов заменены [ADR-0031](0031-zone-splits.md), сайдбар и инспектор — обычными элементами сплита, правило «Разделитель» — разделом «Уточнено в P1.4»
- Дата: 2026-11-09

## Контекст

Рабочая область состоит из четырёх зон в духе JetBrains Fleet: левой, правой, центральной и нижней. Панели могут жить в любой допустимой зоне и обязаны быть там удобны.

## Решение

Раскладка — чистая модель `shellio-layout` без AppKit. Она описывает зоны, вкладки, деревья сплитов, размеры, скрытие и `zoom`, сериализуется и тестируется отдельно. AppKit-адаптер сводит дерево к иерархии `NSView`.

Сопоставление с AppKit:

- Левая зона — `NSSplitViewItem` сайдбара, правая — инспектора, поэтому поведение системное. Поверхности непрозрачны ([ADR-0023](0023-opaque-window-and-shell.md)).
- Центральная и нижняя зоны — вертикальный сплит внутри основной области, нижняя занимает ширину центра.
- Центр поддерживает вкладки и произвольные сплиты. Боковые и нижняя зоны — вкладки и один уровень сплита.

Адаптация идёт по двум осям:

```rust
pub struct Geometry { pub zone: Zone, pub size: SizeClass, pub width: f64, pub height: f64 }
pub enum SizeClass { Narrow, Regular, Wide, ShortBar }
```

- Метод `adapt` разбирает `Zone` исчерпывающим `match` без `_`, чтобы новая зона не прошла незамеченной.
- Панель не копируется на четыре реализации. Это одна модель и разные представления.
- Ниже `min_size` хост показывает компактную заглушку с действием «Развернуть». Нечитаемых миниатюр нет.
- Все действия панели доступны с клавиатуры в любой зоне. В компактном виде путь к ним идёт через раскрытие вглубь или `zoom`.

Правило закреплено в `AGENTS.md` и проверяется контрактным тестом: каждый плагин проходит фикстуры всех зон и размеров.

Перенос панели мышью и клавишами сохраняет `PanelId`, `SessionId` и фокус. Сброс раскладки не останавливает процессы.

## Отвергнутые варианты

- Dock-компонент gpui-kit: отвергнут вместе с GPUI. В испытанной в detached конфигурации были ограничения: полоска закрытой зоны и запрет на перенос последней вкладки.
- Вложенные `NSSplitView` как единственная модель: состояние окажется в AppKit и станет нетестируемым.

## Последствия

Адаптер раскладки — один из самых сложных компонентов фазы 1. `NSView` терминала при обычном переключении вкладок остаётся смонтированным, повторная установка родителя идёт только при явном переносе.

## Основания

`detached/PLAN-EXTENSIBLE.md` (шаг 3, цена `DockArea`), `agterm/ARCHITECTURE.md` (Surface ownership: повторное размещение сбрасывает Metal drawable).

## Уточнено в P1.4 (планирование)

Решение плана P1.4 `layout-zones` [дорожной карты](../roadmap.md), принятое при планировании 2026-11-23. Статус остаётся `Proposed` до вывода исполнения. Деление зон задают [ADR-0031](0031-zone-splits.md) и [ADR-0032](0032-split-and-zoom-buttons.md), здесь оно не меняется. Деревья сплитов и правило «Центр поддерживает вкладки и произвольные сплиты…» раздела «Решение» заменены ADR-0031. Сайдбар и инспектор для левой и правой зон заменены обычными элементами сплита по [ADR-0023](0023-opaque-window-and-shell.md). Команды и чтение записаны в [ADR-0007](0007-control-api.md), хранение — в [ADR-0018](0018-storage-and-config.md), разделы «Уточнено в P1.4 (планирование)».

**Модель.** Crate `shellio-layout` чистый: он зависит только от `serde` и не зависит от `shellio-core` и `shellio-theme`. Модель обобщена по ключу панели (`Layout<P: Copy + Ord>`): тесты используют `u32`, ядро — `Layout<PanelId>`.

```rust
pub enum Zone { Left, Right, Center, Bottom }
pub enum Axis { Stacked, SideBySide }            // Zone::axis(): Left | Right → Stacked
pub struct Layout<P> {
    pub navigator: Option<P>,                    // колонка навигатора левой зоны
    pub zones: ZoneMap<ZoneState<P>>,            // Left — плитка рядом с колонкой
    pub sizes: ZoneSizes,                        // точки: navigator, plate, right, bottom
    pub hidden: Hidden,                          // navigator, plate, right, bottom
    pub only: Option<Zone>,
    pub zoomed: Option<P>,
    pub focus: Vec<P>,                           // история, последняя запись — фокус
}
pub struct ZoneState<P> { pub parts: Vec<Part<P>>, pub last_active: usize }
pub struct Part<P> { pub tabs: Vec<P>, pub active: usize, pub share: u16 }
```

- Зона — список частей вдоль своей оси. Часть — вкладки, активная вкладка и доля зоны. Левая зона держит ещё колонку навигатора: колонка не делится и скрывается отдельно от плитки ([ADR-0024](0024-main-screen-design.md), ADR-0031).
- `Zone` везде разбирается исчерпывающим `match` без `_`.
- Инварианты проверяет `Layout::validate` против множества живых панелей рабочей области. Каждая живая панель стоит ровно в одном месте раскладки, лишних панелей нет. `active` и `last_active` в диапазоне, пустых частей нет, доли непустой зоны больше 0 и в сумме дают 1000. `zoomed` и записи `focus` — панели раскладки, последняя запись `focus` видима при текущем скрытии и `only`.
- **Целые числа.** Размер зоны хранится в точках (`u32`), доля части — в тысячных (`u16`, сумма 1000). Кадры округляются до целых точек, остаток получает последняя часть. Поэтому равенство раскладок до и после перезапуска проверяется побайтно.
- **Панель хранит строковый plugin id** (`navigator`, `terminal`, …). До P1.5 хост для любого id рисует нейтральный вид-заглушку: название, plugin id, зона и класс размера части. P1.5 подставляет фабрики по тому же id без миграции.

**Классы размера и `min_size`.** Пороги взяты из пробы P0.6 ([отчёт](../probes/p0.6-diff-view.md)), числа прототипа не используются. Класс определяется по геометрии части, проверки идут в таком порядке, сравнения строгие:

| Класс | Условие |
| --- | --- |
| `ShortBar` | высота меньше 240 точек |
| `Narrow` | ширина меньше 480 |
| `Wide` | ширина от 1100 |
| `Regular` | остальное |

Ширина ровно 480 даёт `Regular`. `min_size` по умолчанию 200×120, манифест плагина в P1.5 может задать свой. Модель plugin id не знает: операции и геометрия получают `min_size: impl Fn(P) -> MinSize`, а ядро сопоставляет панель её plugin id.

**Геометрию считает чистая модель.** `geometry(&Layout, viewport, &LayoutMetrics, min_size) -> Frames` даёт кадры колонки навигатора, плитки, центра, нижней и правой зон, каждой части, строки вкладок и тела панели, а также `Geometry` тела и флаг заглушки. Адаптер ставит виды по этим кадрам и не полагается на собственный расчёт `NSSplitView`. Поэтому отказ деления по `min_size` одинаков в UI и в CLI, а главный поток не ждёт ядро. Метрики передаются своим малым типом `LayoutMetrics`: заголовок, строка вкладок, промежуток, линия и строка статуса. Ядро и адаптер заполняют его из `shellio-theme`. Строка статуса окна (26 точек) вычитается из области зон.

**Размер окна (`viewport`)** — состояние запуска, а не раскладки. Он не хранится в базе и не входит в публичные команды. Главный поток передаёт ядру размер области содержимого окна внутренним входом. Окно создаётся до ядра, поэтому первый размер уходит до публикации сокета. Дальше размер передаётся при каждом изменении области содержимого, объединяется до конца оборота цикла и не повторяется при том же значении. Без размера (процесс без UI) команды, которым нужно место, отказывают `no_ui`, остальные выполняются. Сохранённые размеры зон — предпочтения: фактические кадры считаются заново по текущему размеру. Окно по-прежнему открывается 1180×720, его кадр не восстанавливается.

**Правила модели.**

- **Раскладка по умолчанию** ([docs/ux.md](../ux.md), «Раскладка по умолчанию»): панель `navigator` в колонке левой зоны, панель `terminal` в центре, фокус на `terminal`. Размеры по умолчанию: колонка навигатора 236 точек ([ADR-0024](0024-main-screen-design.md)), плитка левой зоны 372, правая зона 372, нижняя 236 — значения `L.size` прототипа (`prototype/js/core/state.js`). Плитка, правая и нижняя зоны пусты и появляются по первому действию.
- **Новая панель** открывается в последней активной части зоны, зона без частей получает одну часть. Новая панель без указанной зоны идёт в центр.
- **Деление.** Ось — свойство зоны. Новая часть встаёт правее или ниже текущей, активная вкладка переходит в неё. Деление одиночной вкладки без `open` отказывает `split_needs_panel`, и по этому отказу UI открывает выбор «Открыть в новой части». С `open: <plugin id>` в новой части создаётся новая панель. После деления старая и новая часть делят свою долю поровну, остальные части не меняются. Если любой затронутой части станет меньше `min_size` её активной панели, деление отказывает `split_no_room` с нужным и доступным размером каждой затронутой части. Колонка навигатора не делится: `navigator_not_splittable`.
- **Закрытие и перенос последней вкладки части** убирают часть. Её доля уходит соседней части: левее или выше, иначе правее или ниже. Последняя часть зоны убирает зону, в том числе центр, — пустая рамка не остаётся.
- **Свободная площадь.** Пустой центр отдаёт высоту столбца нижней зоне. Если пусты и центр, и нижняя зона, ширину столбца получает ближайшая непустая боковая плитка: правая зона, иначе плитка левой зоны. Сохранённые размеры зон не меняются и возвращаются, когда центр снова занят. «Нет открытых панелей» на месте центра показывается только тогда, когда вне колонки навигатора нет ни одной панели.
- **Фокус следует за панелью.** Перенос, деление и `zoom` панели с фокусом оставляют фокус на ней в новом месте. Запасной фокус выбирается только тогда, когда панель с фокусом закрыта или скрыта вместе с зоной: последняя активная видимая панель той же зоны, иначе последняя видимая запись истории фокуса, иначе активная вкладка первой части центра.
- **Действие с явной целью.** Деление и `zoom` адресуют панель и сами переводят фокус в её часть перед действием, одной командой и одной ревизией. Кнопка в части без фокуса шлёт одну команду с активной вкладкой этой части (ADR-0032). Панель, которой уже нет, даёт `not_found`.
- **Перенос в зону** кладёт панель в последнюю активную часть целевой зоны и делает её активной вкладкой. Скрытая целевая зона показывается, режим `only` снимается. Панель `navigator`, перенесённая в левую зону, встаёт в колонку навигатора, если колонка пуста, иначе в плитку.
- **Перенос в часть** адресует цель якорем, а не номером: якорь — панель целевой части. Без края вкладка встаёт в часть якоря последней. С краем `before` или `after` рядом с частью якоря вдоль оси зоны создаётся новая часть. Якорь не сбивается, когда исходная часть исчезает и номера сдвигаются. Якорь, которого уже нет, даёт `not_found`.
- **`zoom`** разворачивает одну панель на всю область зон под заголовком, деления не меняются. Развёрнутая панель получает `Geometry` с `Zone::Center` и размером области. Перенос, деление и закрытие развёрнутой панели сначала снимают `zoom`.
- **`only`** (`Ctrl-w o`) ставит в `only` зону с фокусом. Видна только эта зона, она занимает всю область зон, её части остаются. Колонка навигатора видна только при `only` левой зоны. Флаги скрытия не меняются. Повтор `only`, показ другой зоны или перенос в неё снимают режим и возвращают прежнее скрытие.
- **Место проверяют только деление и изменение размера.** Показ и скрытие зон, `only`, перенос и сужение окна место не проверяют и не отказывают: тесная часть показывает заглушку «Развернуть» (ADR-0031). Кнопка заглушки разворачивает панель (`zoom`).
- **Размеры.** Размер зоны ограничен снизу `min_size` активных панелей её частей, сверху — остатком центра не меньше его `min_size`. Вне границ изменение отказывает `resize_out_of_range`. Размер части меняет доли соседей вдоль оси зоны. Выравнивание делает доли частей зоны равными.
- **Сужение окна** раскладку не меняет, части ниже `min_size` показывают заглушку.
- **Без открытой рабочей области** область зон показывает «Рабочая область не открыта». Команды раскладки адресуют рабочую область явно, открытое окно им не нужно.
- **Восстановление.** Раскладка рабочей области переживает перезапуск целиком: зоны, части, доли, размеры, скрытие, `only`, активные вкладки, фокус и `zoom`. `zoom` — состояние раскладки, а не окна.

**AppKit-адаптер.**

- Корень обычного содержимого окна — горизонтальный `NSSplitView` из обычных `NSSplitViewItem`: колонка навигатора, плитка левой зоны, столбец центра, правая зона. Столбец центра — вертикальный `NSSplitView`, где центр стоит над нижней зоной. Части зоны — `NSSplitView` вдоль оси зоны. Режимы сайдбара и инспектора не используются: в macOS 27 они добавляют слои Liquid Glass, которые непрозрачная заливка не убирает (AGENTS.md, ADR-0023).
- Скрытая зона — свёрнутый элемент сплита, её размер хранится в модели. Неявных анимаций нет.
- Плитка части — `Surface` с заливкой панели, радиусом плитки, линией и слоем фокуса [ADR-0027](0027-focused-panel-contrast.md). Внутри плитки стоят строка вкладок и тело. Колонка навигатора плоская, без плитки.
- Вид панели создаётся один раз на `PanelId` и живёт столько же, сколько панель. Смена вкладки скрывает и показывает виды, а перенос и `zoom` переставляют родителя того же вида.
- **Разделитель.** Пока пользователь тянет разделитель, виды двигает AppKit, и адаптер не применяет к этому `NSSplitView` кадры модели. Собственная установка кадров команд не порождает. В конце перетаскивания уходит одна команда изменения размера с итоговым значением.
- Нижняя строка статуса окна держит слот сообщения. Отказы раскладки из UI показываются в ней текстом ADR-0031 и `docs/ux.md`, следующее действие пользователя сообщение убирает. Плашку режима и подсказки добавляет P1.6.
- Имена действий записаны в ADR-0007, а их привязки `Ctrl-w` в `keymap.toml` делает P1.6. До P1.6 подсказки кнопок говорят «Клавиша не назначена» (ADR-0032). Действия доступны кнопками, меню «…» и `shellioctl`, видимость зон — ещё и главным меню «Вид» с `⌘0` и `⌥⌘0` ([ADR-0024](0024-main-screen-design.md)).

**Контрактный тест геометрии.** `shellio_layout::contract` даёт фикстуры всех зон и классов размера, половины и трети центра, половины боковой зоны и `zoom`, а также обвязку проверки `adapt` с отчётом по каждой фикстуре. P1.4 проверяет обвязку на демонстрационной `adapt`, P1.5 прогоняет через неё плагины.

**Передачи:** фабрики видов по plugin id, манифесты с `min_size` и контрактный тест плагинов — P1.5; привязки клавиш и клавиатурный путь к действиям раскладки — P1.6; перенос поверхности libghostty между частями — P2.2. Сброс раскладки и восстановление кадра окна в P1.4 не входят.

## Уточнено в P1.4

Вывод плана P1.4 [`layout-zones`](../plans/completed/20261123-layout-zones.md) по `make check` и приёмочному проходу исполнителя 2026-11-23. Модель и правила раздела «Уточнено в P1.4 (планирование)» реализованы в `crates/shellio-layout`, в ядре и в адаптере `apps/shellio`: чистая часть адаптера — `scene.rs`, применение к AppKit — `layout_ui.rs`. Отрицательных выводов по модели нет, поэтому статус — `Accepted` по правилу плана. Формальный `make e2e` в окружении исполнителя не прошёл предусловия: запущен AeroSpace, источник ввода не латинский, единственный экран внешний, 60 Гц. Поэтому поведение окна подтверждено наблюдательной копией `layout.sh`, а не рубежом ([ADR-0021](0021-testing.md), «Уточнено в P1.4»), и строка P1.4 дорожной карты остаётся ⬜ до формального прогона.

**Подтверждено тестами** (`crates/shellio-layout`, `crates/shellio-core`, `apps/shellio/src/scene.rs`):

- инварианты `validate`, каждая операция на успех и на каждую причину отказа;
- геометрия на окнах 1180×720 и 1440×900 с открытыми и скрытыми зонами, свободная площадь, `only`, `zoom`, границы порогов классов размера;
- контракт: 24 фикстуры покрывают все 16 пар зоны и класса, две из них ниже `min_size` по умолчанию; обвязка `check` проверена на демонстрационной `adapt` с исчерпывающим `match`;
- разница двух сцен в операции адаптера: создание, удаление, перестановка родителя, скрытие и заглушка без пересоздания видов.

**Наблюдение** копией `layout.sh` (`target/e2e/layout/20261123-165339-97795/`): все обязательные пункты матрицы `pass`, кроме `layout-snapshot`, у которого тёмная тема на внешнем экране не судится. Кадры `query.layout`, `ui.inspect` и AX совпали в пределах 1 точки в каждом пункте. Перенос, `zoom` и заглушка виды не пересоздают (`ComponentId` и `ui.stats`). После `app quit` раскладка побайтно равна прежней.

**Уточнения модели**, которых раздел планирования не задавал. Это решения исполнителя по правилу плана, правил раздела они не отменяют:

- **Фокус.** Последняя запись `focus` обязана быть видимой, только когда в раскладке есть видимая панель. Пустая история допустима, только когда видимых панелей нет, например скрыты колонка навигатора и единственная занятая зона. Цепочка запасного фокуса получила четвёртый шаг: любая видимая панель в постоянном порядке, сначала колонка навигатора, затем части по `Zone::ALL`. Без него закрытие терминала в раскладке по умолчанию оставляло видимый навигатор без фокуса. Цепочка начинается с зоны закрытой панели, в левой зоне после плитки идёт колонка навигатора. История фокуса хранится без повторов.
- **Явная цель.** Фокус на панели (`panel.focus`, `panel.select`, деление, `zoom`, новая панель `open`) делает её активной вкладкой, показывает её место (снимает скрытие зоны или колонки и `only` другой зоны) и снимает `zoom` другой панели. Щелчок по вкладке и фокус на её панели дают одно состояние.
- **Деление.** Без `open` в новую часть уходит адресованная панель. С `open` исходная часть сохраняет все вкладки, а новая получает только новую панель и фокус. Нечётную долю большая половина получает правая или нижняя часть. Деление снимает любой `zoom`. Доля 0 после деления — `split_no_room` даже при нулевом `min_size`.
- **Перенос.** Панель колонки навигатора, перенесённая в левую зону, остаётся в колонке. Перенос в часть показывает целевую зону так же, как перенос в зону. Край у одиночной вкладки своей части ничего не меняет. Если край оставил бы долю 0, доли зоны выравниваются: место перенос не проверяет. После закрытия активной вкладки активной становится следующая, у последней — предыдущая.
- **`only`** снимается, когда в его зоне не осталось панелей. Скрытие зоны режима не снимает: это явное действие. `layout.only` без видимой панели с фокусом раскладку не меняет.
- **Фокус по направлению** выбирает среди видимых плиток (колонка навигатора и плитки частей) по ту сторону края плитки с фокусом с положительным перекрытием поперёк направления: меньший зазор, затем большее перекрытие, затем меньшая координата. Без размера окна направление считается по опорному размеру из сохранённых размеров зон с запасом 4000 точек, `no_ui` не возникает.
- **Размеры.** Размер левой зоны — ширина плитки. Нижняя граница — наибольший `min_size` активных панелей вдоль размера и две линии плитки, у нижней зоны ещё строка вкладок. Верхняя граница считается через `geometry`: части центра и нижней зоны не меньше `min_size` в измерении, которое меняет размер. Без столбца центра и нижней зоны свободную ширину получает правая зона, поэтому размер плитки левой зоны ограничивают и её части. Размер правой зоны в этом случае — предпочтение до возвращения столбца. Границу, которую текущий размер уже нарушает, расширяет текущий размер, поэтому в тесном окне диапазон не пуст. Размер скрытой зоны проверяется как у показанной, зона остаётся скрытой. Размер части меняет долю следующей части, у последней — предыдущей.
- **Геометрия.** Начало координат — левый верхний угол области содержимого окна, ось y вниз, размер окна в целых точках. Класс размера и заглушка считаются по телу панели. «Пустая» зона в правиле «Свободная площадь» — зона, которая не показана: без частей, скрыта или вне `only`. Когда окна не хватает, место выдаётся по порядку: колонка навигатора, плитка, правая зона, нижняя зона, каждая не больше остатка, центр получает остаток не меньше 0. Поэтому первым сжимается центр. Развёрнутая плитка занимает область зон с отступом промежутка. Метрики `line` = 1 и `drop_edge` = 24 добавлены токенами в `shellio-theme` со сверкой с `tokens.css`. Ядро и адаптер берут `LayoutMetrics` из одной функции `shellio_core::layout_metrics()`, поэтому кадры `query.layout` и кадры видов считаются по одним метрикам.

**Разделитель.** Правило «Разделитель» раздела планирования («пока пользователь тянет разделитель, виды двигает AppKit») заменено. Встроенное перетаскивание `NSSplitView` выключено: при элементах контроллера и разделителе нулевой толщины оно зацикливало проход `updateConstraints` окна, AppKit бросал исключение, и владелец падал.

- `NSSplitViewItem` требует `NSSplitViewController`, поэтому сплит — подкласс контроллера с подклассом `NSSplitView`. Разделитель нулевой толщины, промежутки между плитками лежат внутри элементов.
- Полоса захвата — собственный вид в промежутке перед следующим элементом, с курсором изменения размера. У разделителя между колонкой навигатора и плиткой полосы нет.
- Полоса двигает границу со следующим показанным элементом, свёрнутые элементы между ними пропускаются. Без столбца центра и нижней зоны плитка левой зоны граничит с правой зоной, и полоса плитки меняет размер левой зоны: свободную ширину получает правая.
- Пока нажата кнопка мыши, за ней идут края содержимого двух соседних элементов. Положения элементов ставит только владелец по квитанции ядра.
- Отпускание со сдвигом от половины точки шлёт одну `layout.resize`, меньший сдвиг возвращает края. Отказ ядра перерисовывает раскладку модели.
- Скрытая зона — `collapsed` элемента, `holdingPriority` 260, `minimumThickness` 0, свёртка по размеру окна выключена. Правило выбора плана «`NSSplitViewItem` двигает кадры сам» не понадобилось.

**Адаптер.**

- Плитки адресуются местом части, а не идентичностью. Когда номера частей сдвигаются, виды панелей переставляются в оставшиеся плитки до удаления лишних.
- Развёрнутая панель лежит на отдельной плитке поверх корня. Корень при этом скрыт, деления под ним не меняются.
- Первый размер окна уходит ядру после загрузки ядра и до публикации сокета, дальше — из `windowDidResize:` с объединением до конца оборота цикла. Галерея размер не передаёт.
- Перетаскивание вкладки начинается со смещения 4 точек. Цель решает чистая функция по кадрам. Строка вкладок или тело части — перенос в эту часть. Полоса края шириной 24 точки внутри тела вдоль оси зоны и не шире половины тела — новая часть с этой стороны, прототип берёт 25 % тела, число плана сохранено. Отмена — вне частей, при `zoom`, над своей частью без края и над краем своей части с одной вкладкой.
- Подсветка цели — слой `Surface` с заливкой `selection` и линией `accent_nav_line`: вся плитка или её половина со стороны новой части.

**Заглушка «Развернуть».**

- Заглушка — отдельный компонент хоста `ExpandStub` со своими счётчиками, а не режим вида панели: вид панели в P1.5 даёт фабрика плагина.
- На каждом месте тела (часть, колонка навигатора, развёрнутая плитка) одна заглушка. Она создаётся при первой нужде, дальше только прячется и показывается.
- Вид под заглушкой скрыт и остаётся на своём месте, поэтому переход через границу `min_size` даёт только скрытие и показ.
- Текст «<название>: здесь тесно» стоит над одной кнопкой «Развернуть» (`layout.zoom` панели этого места). Второй кнопки прототипа «В центр» нет: план называет только `zoom`. Щелчок в тело заглушки мимо кнопки переводит фокус на панель.
- Колонка навигатора получает заглушку так же, как часть. Развёрнутая панель ниже `min_size` показывает заглушку без кнопки: разворачивать дальше некуда. В низком теле текст уходит раньше кнопки.
- Заглушка колонки, развёрнутой панели и низкого тела проверены только тестами: окно P1.4 не сужается ниже 1180×720, и эти места в нём не возникают.

**Отрицательные выводы и передачи:**

- Ширину колонки навигатора ни одна команда P1.4 не меняет, у её разделителя нет полосы захвата. Изменение ширины колонки — P1.6 вместе с шагами размера.
- `docs/ux.md` говорил, что перетаскивание на край части создаёт новую часть, «если обеим частям хватает места». Правило «Место проверяют только деление и изменение размера» перенос не ограничивает: тесная часть показывает заглушку. `docs/ux.md` исправлен по правилу.
- Новую панель создаёт только `layout.split --open`, а колонка навигатора не делится. Если вне колонки навигатора панелей не осталось, интерфейс P1.4 новую панель не открывает, а CLI — только переносом навигатора в центр и делением. Открытие панели в зону — `open-or-focus` P1.5 (`Layout::open`).
- Формальный `make e2e` с тремя сценариями — владельцу (Post-Completion плана).

## Условие пересмотра

P0.3 покажет, что перенос Metal-поверхности между зонами вызывает неприемлемые артефакты.
