# ADR-0019: Подпись, автообновление, Homebrew

- Статус: Accepted (владелец не использует Apple Developer ID), механизм проверяется в P0.5
- Дата: 2026-11-09

## Контекст

Нужны установка через Homebrew и автоматическое обновление. Платной учётной записи Apple Developer не будет, поэтому нотаризации нет. Подпись должна быть постоянной: ad-hoc подпись меняет требование к коду при каждой сборке, и доступ к Keychain и разрешения слетают.

## Решение

**Подпись.** Постоянная самоподписанная идентичность `Shellio Dev`, сертификат и закрытый ключ хранятся в секретах CI. Bundle ID и designated requirement стабильны. Сохранение разрешений TCC для GUI и хостов старого поколения не считается автоматическим и проверяется в P0.5.

**Установка.** Собственный tap с cask: `depends_on arch: :arm64`, `auto_updates true`, `binary` для `shellioctl`, снятие карантина в `preflight_steps` со staged-копии. Сборка только под arm64. Ошибка снятия карантина приводит к понятному сообщению при установке, так как без нотаризации приложение иначе не запустится.

**Обновление.** Собственный механизм:

1. При запуске и раз в сутки читается `latest.json` из последнего релиза.
2. Файл и архив проверяются подписью minisign с вшитым публичным ключом.
3. Загрузчик приложения не ставит атрибут карантина (`LSFileQuarantineEnabled` не включён). Проверяется полученный артефакт.
4. Кодовая подпись новой версии проверяется по сертификату и требованию, а не по отображаемому имени.
5. Новая версия подготовлена на той же файловой системе, UI показывает готовность в статус-баре.
6. Замена бандла идёт по протоколу, который выбирает P0.5.
7. Новый GUI подключается к тем же сессиям.

Требования к протоколу замены:

- Обычный `rename` не заменяет непустой каталог, а два `rename` подряд неатомарны.
- Кандидаты: `renamex_np` с `RENAME_SWAP` на APFS либо журналируемая последовательность с восстановлением из любой промежуточной точки. Выполняет короткоживущий помощник после выхода GUI.
- Старая версия сохраняется до подтверждения работоспособности новой.
- P0.5 проверяет убийство помощника и нового GUI на каждой границе, нехватку места, отсутствие прав, передачу `flock` и сокета.

Живые хосты не запускаются из бандла. Активная версия `shellio-host` копируется в `runtime/<version>/`. Старые поколения удаляются, когда их не использует ни одна сессия.

Версия протокола хоста и версия схемы хранения независимы. Если новая версия не совместима с работающими хостами, активация откладывается с явным сообщением. Агенты молча не перезапускаются.

Перед миграцией схемы делается согласованная резервная копия средствами SQLite. Автоматический откат без потери новых данных не обещается, если миграция необратима.

## Отвергнутые варианты

- Sparkle: технически работает с EdDSA и без Developer ID. Принята стоимость своего установщика и восстановления ради полностью Rust-кода и управления связкой GUI, хостов и runtime.
- Curl-установщик как основной путь: требование — Homebrew.

## Последствия

- Браузерная загрузка блокируется Gatekeeper, поддерживаемые пути — Homebrew и встроенное обновление.
- Приватный ключ minisign и сертификат — самое ценное в проекте, их потеря означает ручную переустановку.
- Релизы должны быть доступны без авторизации. Для приватного репозитория нужен отдельный публичный источник.

## Основания

- `detached/README.md`: самоподписанная идентичность и minisign. `detached/crates/app/src/update.rs:174–192`: два `rename`, что показывает, чего избегать. `detached/PLAN-EXTENSIBLE.md`: карантинный бинарник завершается при запуске, без карантина работает.
- `agterm/packaging/agterm.rb`: техника снятия карантина. Само это приложение нотаризовано, поэтому работу без нотаризации подтверждает только P0.5.
- `agterm/CLAUDE.md:180`: перезапись `zmx` и session host под живыми демонами вызывает `SIGKILL (Code Signature Invalid)`.
- [Homebrew Cask Cookbook](https://docs.brew.sh/Cask-Cookbook), [Sparkle](https://sparkle-project.org/documentation/), `man 2 rename`.

## Условие пересмотра

Ужесточение Gatekeeper в новой macOS или появление Developer ID.

## Уточнено в P0.1

План [toolchain-bootstrap](../plans/20261111-toolchain-bootstrap.md) конкретизирует подпись. Решение не меняется.

- Bundle ID — `io.github.dsbasko.shellio`.
- Designated requirement задаётся явно и хранится в `scripts/signing/requirement.txt`: `designated => identifier "io.github.dsbasko.shellio" and certificate leaf = H"<SHA-1 сертификата>"`. Сравнивается каноническая форма из `codesign -d -r-`, а не исходный текст. Хэш сертификата публичен, закрытый ключ в репозиторий не попадает.
- Подпись выполняется по SHA-1 сертификата, а не по отображаемому имени. Без идентичности сборка бандла завершается ошибкой, ad-hoc подпись не подставляется.
- Доверие к сертификату не требуется. Самоподписанный сертификат OpenSSL с назначением Code Signing подписывает бинарь с явным requirement и проходит `codesign --verify --strict` на macOS 27.0.1 без доверия. Это проверено во временном разблокированном keychain, поведение login keychain может отличаться.
- Hardened runtime в P0.1 не нужен. Сохранение разрешений TCC по-прежнему проверяет P0.5.
