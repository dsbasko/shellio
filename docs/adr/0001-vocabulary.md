# ADR-0001: Словарь и иерархия сущностей

- Статус: Accepted
- Дата: 2026-11-09

## Контекст

В требованиях слово «окно» означает и рабочую область, и панель внутри неё, а в macOS ещё и `NSWindow`. Слово «воркспейс» в agterm означает другой уровень. Без единого словаря модель, CLI и документация расходятся с первого плана.

## Решение

| Термин в коде | В интерфейсе | Что это |
| --- | --- | --- |
| `Workspace` | Воркспейс | Глобальный контейнер: «Работа», «Личное» |
| `Project` | Проект | Набор из одного или нескольких репозиториев и папок, привязки к аккаунтам GitHub/GitLab |
| `Repository` | Репозиторий | Один git-репозиторий проекта с его remotes и worktree |
| `Worktree` | Worktree | Рабочая копия репозитория со своими HEAD, index и файлами |
| `Workbench` | Рабочая область | Именованная раскладка с панелями внутри проекта. В требованиях это «окно рабочей области» |
| `Zone` | Зона | Левая, правая, центральная или нижняя часть рабочей области |
| `Panel` | Панель | Экземпляр плагина, показанный вкладкой в зоне |
| `Plugin` | — | Зарегистрированный тип возможности: терминал, агент, blame, ревью |
| `Session` | Сессия | Долгоживущий процесс за терминальной панелью, с поколением `generation` |
| `Agent` | Агент | Зарегистрированный экземпляр Claude Code, Codex и других внутри сессии |
| `NSWindow` | Окно macOS | Только окно операционной системы |

Иерархия: `Workspace → Project → Workbench → Zone → Panel`. `Project` содержит `repositories[]` с первого дня. Git-операция всегда адресует конкретный репозиторий и worktree, а `Workbench` хранит активный из них.

`PanelId`, `SessionId` и `AgentId` — разные сущности. Перенос панели между зонами не меняет ни одну из них. Перезапуск процесса создаёт новое поколение сессии.

По умолчанию все рабочие области показываются в одном `NSWindow`.

## Отвергнутые варианты

- Заимствовать `Window → Workspace → Session` из agterm: там `Window` — это окно ОС, что здесь уже занято.
- Один репозиторий на проект: проще, но проекты из нескольких репозиториев потребовали бы переделки модели. Несколько репозиториев — осознанное расширение.

## Последствия

Словарь обязателен для кода, CLI и документов. Тексты интерфейса используют русские названия из таблицы.

## Основания

Требования владельца. `agterm/ARCHITECTURE.md`: модель `WindowLibrary` → `AppStore` → `Workspace` → `Session`.

## Уточнено в P1.1

Решение плана P1.1 `core-domain`, принятое при планировании 2026-11-21. Словарь и иерархия не меняются.

- Идентификатор каждой сущности — UUIDv7 в собственном newtype: `WorkspaceId`, `ProjectId`, `ProjectRootId`, `WorkbenchId`, `PanelId`, `SessionId`, `AgentId`. Идентификатор одной сущности нельзя передать вместо другой: это ошибка типа.
- В CLI, JSON и переменных окружения (`SHELLIO_SESSION_ID`, `SHELLIO_PANEL_ID`) идентификатор записывается канонической строкой UUID в нижнем регистре с дефисами. Разбор принимает только каноническую форму в любом регистре и версию UUID не проверяет: внешний идентификатор не обязан быть v7.
- В `state.db` идентификатор хранится `BLOB` ровно из 16 байт. Другая длина при загрузке — повреждённая запись.
- Новый идентификатор выдаёт только внедряемый генератор: `Uuid::now_v7()` в продукте, последовательный в тестах. Никакая логика не опирается на порядок идентификаторов.
- `PanelId`, `SessionId` и `AgentId` в P1.1 заведены только типами. Таблицы панелей появляются в P1.4, сессий — в P2.1, агентов — в P2.5.

## Условие пересмотра

Появление сущности, которая не укладывается в иерархию.
