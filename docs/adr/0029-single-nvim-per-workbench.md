# ADR-0029: Один nvim на рабочую область, по необходимости

- Статус: Accepted (решение владельца)
- Дата: 2026-11-10
- Заменяет в [ADR-0017](0017-nvim.md) выбор панели «существующий редактор рабочей области или новый» и вкладку, названную по открытому файлу. Для вкладки nvim заменяет в [ADR-0004](0004-process-model.md) выбор «закрыть вид или остановить» при закрытии панели. Остальное в ADR-0017 остаётся в силе.

## Контекст

Редактор был вкладкой с именем файла и открывался вместе с раскладкой. Владелец видит в нём не открытый файл, а запущенный nvim, который появляется при необходимости. Запущен может быть максимум один.

## Решение

### Граница

- Управляемый nvim: не больше одного на рабочую область. Он запускается в её worktree ([ADR-0017](0017-nvim.md)).
- nvim, набранный вручную в обычном терминале, не управляется shellio и в лимит не входит.

### Вкладка

- Вкладка называется `nvim`. Файлы, буферы и вкладки показывает сам nvim.
- В навигаторе и поиске рядом с сессией может стоять текущий файл по отчёту Lua-плагина. Это состояние, а не заголовок.

### Запуск

- При открытии рабочей области nvim не запускается.
- Запускают его `Space e` (`editor.open`), переход к файлу из diff, blame, ревью, пайплайнов и поиска, а также `shellioctl editor open <файл>[:<строка>]`.
- Запуск принадлежит одному владельцу. Он создаёт сессию или подключается к ней по стабильному `SessionId` рабочей области, в том числе после перезапуска GUI ([ADR-0004](0004-process-model.md)). Переходы, пришедшие во время запуска, ждут готовности RPC и второй процесс не создают.
- Переход к файлу при живом nvim уходит по RPC в тот же экземпляр, вкладка получает фокус. Возврат к источнику из [ADR-0017](0017-nvim.md) сохраняется.

### Жизненный цикл

- Закрытие вкладки: nvim и несохранённые буферы продолжают жить, сессия видна в «В фоне». Следующий запуск возвращает тот же экземпляр.
- Выход из nvim с кодом 0 убирает вкладку. Другой код оставляет состояние «Завершена» с действием «Запустить заново».
- Остановка из shellio выполняет обычный выход nvim, который сам проверяет изменённые буферы. Число изменённых по RPC нужно только для текста подтверждения. Если nvim отказался выйти, остановка не считается успешной и сессия не становится завершённой. Успех проверяется по процессам.
- Нет связи с RPC при живом процессе: вкладка сообщает «Нет связи с nvim, управление из shellio недоступно». Поверхность остаётся рабочей, выйти можно в самом nvim. Действия: переподключиться и вернуться к nvim. Принудительное завершение — отдельное действие с предупреждением, что состояние буферов неизвестно. Второй экземпляр не запускается.
- shellio не меняет каталог живого nvim вслед за активным репозиторием области. Файл другого репозитория открывается по полному пути. Команды nvim вроде `:cd` работают как обычно.
- Историческая ревизия открывается буфером только для чтения в том же nvim.

## Отвергнутые варианты

- Один nvim на всё приложение. Владелец выбрал рабочую область: у каждой свой worktree и свои несохранённые буферы.
- Вкладка на каждый открытый файл. Владелец видит в редакторе запущенный nvim, а не файл.
- Запуск вместе с рабочей областью. Процесс работал бы и там, где редактор не нужен.
- Учитывать nvim, запущенный вручную в терминале. Для этого пришлось бы следить за командами в чужой оболочке.

## Последствия

- Поток 10 в `docs/ux.md` начинается с запуска nvim, если его нет.
- Строка «Редактор» в таблице адаптации к зонам называется «nvim».
- План P3.6 включает владельца запуска, состояние недоступного RPC и проверку буферов при выходе.

## Основания

- Требование владельца от 2026-11-10: «Это не будет отдельно открытый файл. Это будет запущенный инстанс nvim (при необходимости). Максимум может быть запущен 1 инстанс nvim».
- Ответы владельца: граница — рабочая область, nvim в обычном терминале не считается.

## Условие пересмотра

Потребность в двух редакторах в одной рабочей области или в общем редакторе для нескольких областей.
