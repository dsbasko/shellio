# ADR-0033: Панель «История» вместо Blame

- Статус: Accepted (решение владельца)
- Дата: 2026-11-11
- Заменяет плагин `blame` из [ADR-0008](0008-plugin-system.md) и раздел о blame в [ADR-0014](0014-git.md).

## Контекст

Исходное требование владельца: «В рамках рабочей области можно посмотреть git blame. Несколько инстансов git blame в одной рабочей области недоступно. При нажатии на коммит, можно посмотреть список файлов коммита и diff на каждый файл». По нему в план вошла панель Blame: код файла с колонкой коммитов, затем коммит, его файлы и diff ([ADR-0008](0008-plugin-system.md), [ADR-0014](0014-git.md), P3.5).

Владелец уточнил, что имел в виду не blame, а GitLens: историю коммитов, из которой открываются файлы коммита и их diff. Из возможностей GitLens владелец выбрал граф коммитов и историю, без изменений в nvim.

## Решение

### Панель

- Плагин `history`, панель «История». Одна на рабочую область (`PerWorkbench`). Повторное открытие переводит существующую панель на новый файл, строки или коммит, «Назад» возвращает прежний вид.
- Панель показывает историю репозитория. `HEAD`, upstream и рабочая копия берутся у worktree рабочей области. Панель только читает репозиторий: checkout, cherry-pick, revert, reset и rebase из неё не выполняются.
- Выбор держится по SHA. После обновления refs и переноса панели курсор остаётся на том же коммите.

### Что показывает

- **Граф коммитов.** Линии ветвей и слияний, ветки, теги, `HEAD` и upstream текущей ветки. По умолчанию показаны все локальные ветки с их upstream, `b` оставляет только текущую ветку.
- **Строка коммита.** Линии графа, сообщение, ветки и теги, автор, относительная дата, короткий SHA.
- **Рабочая копия.** Если есть незакоммиченные изменения, над `HEAD` стоит строка «Рабочая копия». `Enter` на ней открывает «Изменения».
- **Поиск.** `/` ищет по сообщению, автору, SHA и пути файла. Совпадения идут списком без линий графа: соседние строки выдачи не обязательно связаны родством.
- **Коммит.** Сведения: автор, дата, сообщение целиком, родители, ветки и теги. Ниже файлы со статусом A, M, D или R и числом строк. `Enter` на файле открывает diff тем же `DiffView`, что в «Изменениях». Diff коммита слияния строится относительно первого родителя, и сведения называют этого родителя. Корневой коммит сравнивается с пустым деревом.
- **История файла.** Коммиты, менявшие файл, с учётом переименований. Коммиты, не менявшие файл, скрыты, как и слияние, совпадающее по файлу с одним из родителей: история идёт в этого родителя. Линии строятся по родителям, которые git переписывает для пути при `--parents`.
- **История строк.** Коммиты, менявшие строку или выделенный диапазон, новые сверху. Первый коммит списка последним менял эти строки. Слияние, не менявшее диапазон относительно одного из родителей, ведёт в этого родителя, как `git log -L`. У каждого коммита виден diff только этих строк.
- **Строки и ревизия.** Номера строк рабочей копии переводятся в номера `HEAD` по diff рабочей копии. Строка удаления в diff берётся со старой стороны, в родительской ревизии. Строка, которой ещё нет ни в одном коммите, показывает только «Рабочую копию» с пояснением, а не историю другой строки с тем же номером.
- **Сравнение ревизий.** `c` отмечает базу, `c` на втором коммите задаёт цель и открывает список различающихся файлов и их diff. Сравниваются деревья базы и цели, как `git diff <база> <цель>`, а не изменения от общего предка. Строка «Рабочая копия» тоже может быть целью.
- **Состояния.** Пустой репозиторий, detached `HEAD`, неполная история после shallow clone, бинарный или слишком большой diff и отсутствующий объект показаны явно.

### Источник данных

- Граф: `git log` по локальным веткам и их upstream со своим форматом, `--topo-order` и `--parents`. Ветки и теги берутся из `git for-each-ref`. Коммиты приходят порциями по 500, следующая порция запрашивается при прокрутке. Раскладку линий считает чистая модель в `shellio-git` вне главного потока.
- История файла: `git log --follow` по пути со своим форматом.
- История строк: `git log -L <начало>,<конец>:<путь>`. Diff диапазона берётся из того же вывода.
- Коммит: сведения из `git show -s` со своим форматом. Файлы из `git diff --name-status -M <первый родитель> <коммит>`, diff файла из `git diff` той же пары по пути. У корневого коммита вместо родителя пустое дерево. Combined diff слияния, который по умолчанию даёт `git show`, не используется.
- Сравнение: `git diff --name-status -M` между двумя ревизиями, затем diff выбранного файла.
- `git blame` не используется.
- Загрузка инкрементальная и отменяемая ([ADR-0014](0014-git.md)). Закрытие вида отменяет его загрузку. Коммиты и refs кэшируются на уровне репозитория, `HEAD` и рабочая копия по `WorktreeId`, как в ADR-0014. Кэш сбрасывает watcher из P3.1.

### Адаптация к зонам

Вид выбирается по геометрии части зоны ([ADR-0031](0031-zone-splits.md)): половина центра может быть узкой.

- Боковая зона и узкая часть центра: граф в одну колонку из линий, сообщения и даты. Сведения коммита и файлы открываются вглубь, diff unified.
- Широкая часть центра (`Wide`): граф со всеми колонками и сведения выбранного коммита справа. Diff файла открывается на месте графа, side-by-side при достаточной ширине.
- Нижняя зона: граф строками в ширину, файлы выбранного коммита рядом, diff на месте файлов. В узкой части нижней зоны вид как в боковой.
- Ветки, теги и родители доступны текстом в строке и в сведениях. Тон линий не единственный носитель смысла, VoiceOver читает строку как сообщение, автора, дату и ветки.
- Ниже `min_size` показывается заглушка «Развернуть».

### Команды и клавиши

- Команда шины `history.open { path?, lines?, rev?, side? }`. Без аргументов открывает граф, с `path` историю файла, с `path` и `lines` историю строк, с `rev` переводит курсор на коммит. `lines` относятся к ревизии `rev`, по умолчанию к рабочей копии. `side` указывает сторону diff для строки удаления.
- `Space g l` — история рабочей области (`history.open`). `Space g h` — история текущего файла (`history.file`). `Space g L` — история текущей строки или выделения в nvim (`history.line`), в режиме навигации. Из режима ввода сначала `Ctrl-\`: клавиши ввода nvim не перехватываются.
- В панели: `j/k` — строки, `Enter` или `l` — вглубь, `h` или `Ctrl-o` — назад, `/` — поиск, `b` — все ветки или текущая, `c` — сравнение, `g f` — открыть файл в nvim на строке. Ревизия, отличная от рабочей копии, открывается в nvim только для чтения.
- CLI: `shellioctl history open [--file <путь>[:<начало>-<конец>]] [--rev <sha>]` и `shellioctl history read`, который возвращает вид панели в JSON: режим, фильтр, выбранный коммит и файл.

### Компонент графа

Линии графа рисует ячейка `VirtualList` в `shellio-appkit` по готовой раскладке модели. Это новый элемент набора компонентов [ADR-0002](0002-ui-stack-appkit.md). Кадры и память проверяются в P3.5 на истории из 100 тыс. коммитов, большие репозитории ещё раз в P5.4.

## Отвергнутые варианты

- Оставить панель Blame. Владелец имел в виду другое.
- Автор и коммит текущей строки серым текстом в конце строки nvim и по наведению, как inline blame в GitLens. Владелец выбрал вариант без изменений в nvim.
- Подписи над функциями с авторами и последним изменением, как CodeLens в GitLens. По той же причине.
- Только граф, без истории файла, истории строк и сравнения. Владелец выбрал полный вариант.
- Действия с ветками и коммитами из графа. Их не просили, а index и ветка рабочей области меняются в «Изменениях» и терминале.
- Отдельные панели для графа, истории файла и истории строк. Нарушили бы «одну на рабочую область» и разнесли бы одни и те же действия по трём местам.

## Последствия

- План P3.5 называется `git-history` вместо `blame-history`. Приёмка идёт на настоящем git во временных репозиториях ([ADR-0021](0021-testing.md)): слияние, корневой коммит, переименование и удаление, ревизия в nvim, узкая часть и `ShortBar`, отмена загрузки, одна панель на рабочую область.
- `Space g L` берёт строку и выделение из nvim через RPC, поэтому история строк из nvim появляется в P3.6. До него она открывается из diff и командой `history.open` с `lines`.
- Тексты ADR-0001, ADR-0008, ADR-0014, ADR-0017, ADR-0020, ADR-0029 и ADR-0031 упоминают blame как прежний план. Действует этот ADR.

## Основания

- Уточнение владельца от 2026-11-11: «Я перепутал git blame с git lens. Нужно убрать из плана проекта git blame и добавить git lens». Выбран вариант с графом и историей, без изменений в nvim.
- Возможности GitLens для VS Code: Commit Graph, Commit Details, File History, Line History, сравнение ревизий. Код GitLens не используется, берутся только идеи.
- Документация git: `git log` с `-L`, `--follow` и `--topo-order`, `git for-each-ref`.

## Условие пересмотра

Владелец захочет видеть автора строки прямо в nvim.
