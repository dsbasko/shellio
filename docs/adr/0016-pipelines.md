# ADR-0016: Пайплайны по нескольким репозиториям

- Статус: Proposed
- Дата: 2026-11-09

## Контекст

Нужно проверять пайплайны проекта из GitHub и GitLab, даже если их несколько. Иерархии провайдеров различны: GitLab pipeline, stages, jobs; GitHub workflow, run, jobs и отдельные checks.

## Решение

Плагин `pipelines` с кардинальностью `PerWorkbench` агрегирует явно выбранные репозитории и remotes проекта. Идентичность запуска: хост, проект, запуск, попытка, ref, SHA. Нормализуется только общий статус, детали провайдера сохраняются.

Опрос: ETag, адаптивный интервал и backoff, активный при видимой панели или идущем запуске, редкий в фоне, без опроса при отключённой сети. Устаревший запуск не выглядит как проверка текущего коммита.

Интерфейс: статус проекта в статус-баре, список с группировкой по репозиторию, jobs, лог, ссылка, retry, cancel и ручной шаг при наличии возможности. Завершение следимого запуска даёт системное уведомление. Упавший job можно передать агенту с закреплёнными репозиторием, ref и логом.

GitHub Actions не исчерпывают проверки: сторонние check runs показываются отдельно.

## Отвергнутые варианты

- Общая иерархия stages/jobs для обоих провайдеров: искажает GitHub.
- Постоянный опрос всех проектов: расход и лимиты API.

## Последствия

Child и downstream pipelines GitLab требуют отдельной проверки на реальном API.

## Основания

`detached/crates/core/src/forge/mod.rs:65–90`, [GitHub check runs](https://docs.github.com/en/rest/checks/runs).

## Условие пересмотра

Требование одновременного наблюдения за всеми проектами.
