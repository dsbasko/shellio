# Архитектура shellio

shellio — нативный для macOS хаб разработчика на Rust: воркспейсы, проекты, рабочие области с терминалами, агентами, git, ревью и nvim. Решения и их причины описаны в [docs/adr](adr/README.md). Термины определены в [ADR-0001](adr/0001-vocabulary.md).

## Стек

| Часть | Выбор | ADR |
| --- | --- | --- |
| Язык собственного кода | Rust 2024 | 0002 |
| Интерфейс | AppKit через `objc2`, непрозрачные поверхности | 0002, 0023 |
| Терминал | Полный libghostty, закреплённая ревизия | 0003 |
| Постоянство сессий | Отдельный хост на сессию | 0004, 0005 |
| Асинхронность | Главный поток AppKit, актор состояния, runtime `tokio`, рабочий пул | 0020 |
| Хранение | SQLite, TOML, Keychain | 0018 |
| Git | Внешний `git` | 0014 |
| Редактор | Один `nvim --listen` на рабочую область, по необходимости | 0017, 0029 |
| Поставка | Самоподписанная идентичность, minisign, Homebrew tap | 0019 |

Платформа: macOS 27, Apple Silicon.

## Процессы

```text
                     shellioctl, хуки агентов, фоновые задачи
                                    │ Unix-сокет, JSON
┌───────────────────────────────────▼───────────────────────────────┐
│ shellio (единственный GUI-процесс)                                │
│                                                                   │
│  главный поток: AppKit, поверхности libghostty, KeyRouter         │
│        ▲ снимки состояния            │ Command                    │
│        │                             ▼                            │
│  актор состояния: домен, раскладка, плагины, события с ревизией   │
│        │                                                          │
│  пул: git, forge, сэмплер, сообщения, SQLite                      │
└───┬───────────────────────────────────────────────────────────────┘
    │ PTY поверхности
┌───▼──────────────┐      ┌──────────────────┐
│ attach-клиент    │─────▶│ shellio-host     │  по одному на сессию,
└──────────────────┘ сокет│ экран, второй PTY│  переживает GUI
                          └───┬──────────────┘
                              ▼
                     shell, claude, codex, nvim
```

Закрытие окна, обновление и падение GUI не завершают сессии. Управляющий API и доставка сообщений работают, пока запущено приложение. Полный контракт — в [ADR-0004](adr/0004-process-model.md).

## Правила зависимостей

1. `shellio-core` и остальные чистые crate не зависят от AppKit.
2. Модель плагина зависит от `shellio-plugin-api` и сервисных crate. Фабрика вида выполняется на главном потоке и дополнительно использует безопасные компоненты `shellio-appkit` и `shellio-ghostty`. Зависимость от другого плагина запрещена.
3. Конкретные плагины знает только `apps/shellio`.
4. `unsafe` Objective-C находится в `shellio-appkit` и `shellio-ghostty`.
5. Плагины взаимодействуют только через команды шины.

## Поток данных

```text
клавиша, меню, палитра, CLI → Command → актор → новое состояние + Event(ревизия)
                                                   ├─ главный поток: снимок и применение разницы
                                                   ├─ подписчики CLI: журнал с курсором
                                                   └─ плагины: подписки
```

У каждого действия один обработчик. Интерфейс не изменяет домен напрямую.

│    ◌ claude  zsh  Пайплайны  Ресурсы                │ сообщение коммита│
│    ● codex│ ┌─────────────────────────────────────┐ │ [AI]    [Commit] │

Все поверхности непрозрачны, глубина задаётся тоном, линией и тенью ([ADR-0023](adr/0023-opaque-window-and-shell.md)). Тулбар отвечает на вопрос «где я и куда перейти», статус-бар на вопрос «что происходит». Заголовок панели — вкладка. Палитра, подсказки и другие наложения — отдельные плавающие панели поверх поверхностей libghostty, так как те являются `NSView` со своим Metal-слоем.

## Подсистемы

Терминал: `shellio-ghostty` и `plugins/terminal` создают поверхность, `shellio-session` управляет хостом. Каждый агент — своя терминальная панель с адаптером и статусами ([ADR-0030](adr/0030-agent-panel-per-agent.md)). Зоны делятся на части по одной оси ([ADR-0031](adr/0031-zone-splits.md)).

Агенты: профиль запуска → адаптер → статусы через хуки → сообщения через `state.db` и механизм доставки агента.

Git: `shellio-git` выполняет команды, кэширует статус по `WorktreeId` и отдаёт события. Одна служба обслуживает все панели. Панели не запускают свои опросы.

Forge: `shellio-forge` — общая модель с адаптерами, журнал черновиков в `state.db`.

Ресурсы: один сэмплер, измеренная сводка процессов и отдельная оценка данных внутри приложения.

## Стартовые бюджеты

Значения уточняются по замерам P0.8 и P5.4. Превышение уточнённого бюджета считается дефектом.

| Показатель | Цель |
| --- | --- |
| Запуск до интерактивного окна | до 500 мс |
| Реакция на клавишу в `Navigation` | до 16 мс |
| CPU GUI в простое при видимых панелях | до 1% |
| Скрытые поверхности | без рендера и swap chain |
| Память GUI без терминалов | до 150 МБ |
| Открытие diff на 100 тыс. строк, первый экран | до 200 мс |
| Прокрутка diff | без потери кадров при 120 Гц |
| Стоимость сэмплера | до 0,5% CPU |

## Главные риски

| Риск | Что с ним делаем |
| --- | --- |
| Компоненты AppKit на Rust окажутся слишком дорогими | P0.2 и P0.6, рубеж в ADR-0002 |
| Внутренний API libghostty меняется | Закреплённая ревизия, отдельный план на обновление |
| Хост, attach и восстановление экрана работают не для всех программ | Матрица P0.4 |
| Обновление завершает сессии | P0.5, отдельные версии протокола и runtime |
| Без Developer ID ужесточится Gatekeeper | P0.5 на целевой macOS, условие пересмотра ADR-0019 |
| Хуки агентов меняются | Адаптеры, матрица версий |
| Смена ревизии во время ревью | Журнал, якоря, P0.7 |
